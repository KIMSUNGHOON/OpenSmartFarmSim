## 실패 재현과 수정

첫 실제 SCRAM 실행은 **19통과·1실패 / 1,092.79초**, 원 명령 종료1이다.
정상120걸음과 수치 hold60걸음의 한 호출/분할 호출·DB 게시/재조회는 통과했다.
25시간 입력의32회 계산도 진행했지만 이후 원 사건 행 비교에서 실패했다.
서버의 보호 문맥이 시험 본문의 예외를 일반 custody hold로 바꿔 원 차이를 가렸다.

PG 없는 원32commit 재현에서 sample은 모두 일치했고 event의 `input_id` 한 열이 달랐다.
기록된 공개 API 응답은 이 내부 열을 내보내지 않는데 시험이 내부 원행과 그대로 비교했다.
기대 사건에 원 프로그램의 같은 시각·removal input ID를 결속했다. 개수는 strict zip,
시각은 별도 assertion으로 확인하며 원값이나 출처 ID를 제거하지 않는다.
수정한 순수 재현은 종료0·원9sample/2event가 모두 일치했다.

원인이 확인된 긴 시험만 다시 실행해 **1통과·19미선택 / 494.61초**, 원 명령 종료0을 얻었다.
최신 경량17개도 통과했다. 이전 정상/hold 두 사례와 수정한 긴 사례의 분할 증거이며,
수정 판본의 전체20개를 한 번에 실행했다고 주장하지 않는다.
