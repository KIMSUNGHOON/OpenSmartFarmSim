## 구현 범위

[5파일 계약](../contracts/web-crop-result-catalog-client-v1.md)에 따라 기존 `createApi`에
생장/수확 metadata 목록 조회를 추가했다. 닫힌 요청·응답, 같은 농장/판본, 원 UTC 소수6자리와
ID의 내림차순·고유성·cursor 경계, 취소/늦은 응답을 검사한다. 기본10/최대20건,
30초/64KiB와 기존 Bearer transport를 유지한다. 자동 페이지 조회나 계산을 시작하지 않는다.
선택 결과의 원 값/현재 권리 검사는 기존 결과 조회가 담당한다.

[공개 시험 fixture](../web/e2e/crop-result-catalog-recorded-responses.json)는 별도 소유 DB의
실제 HTTPS 성공 body7개를 UTF-8 원문으로 보존했다. 원 bytes/SHA·요청 query를 각각 대사했다.
기존 정상 producer의 추가20건과 원 보존1건을 재사용했고 새로 계산하거나 재서명하지 않았다.
동률 경계는 새 소유 행20건의 시각을 바꾼 시험이며 원 보존 행의 시각은 유지했다.
시험의 잘못된/빈/미세 UTC 응답 변형은 소프트웨어 반례다.

## WSL 자원과 미수용 범위

원 전체 계산과 사용자 미리보기를 포함한 RSS 합1GiB/단일512MiB를 유지했다.
첫 두 전체 웹 시도는 합계 초과로 종료했고, 한 threaded worker/heap128MiB의 다음 검사 자식은 통과했다.
그 명령의 후속 빌드, 중첩 npm 제거 후 빌드, Rayon1 설정, CPU1/arena2 설정의 빌드도 합계 한도를 넘었다.
마지막 합계는1,075,720,192bytes, 한 시도는 단일555,122,688bytes로 단일 상한도 넘었다.
한도를 올리거나 원 계산/미리보기를 중단하지 않았다. 이 설정의 일반적 메모리 절감 효과를 주장하지 않는다.
전체 controller 종료는 모두1이며 **검사 자식 성공과 전체 실행 성공을 구분한다.**

모든 시도에서 source1,524개와 기존 `web/dist`는 유지됐다. 원 계산·미리보기 네 보호 PID의
identity가 같고 검사 자식은 남지 않았다. native 동시 RSS 최대844,394,496bytes/단일148,541,440bytes다.
12:20 관측에서 원 전체 계산은 같은 프로세스의 commit231/921,913걸음으로 진행 중이며 완료가 아니다.
미리보기 HTTP200을 확인했다. 이 화면은 여전히 별도 DB의 저장3시점이며 SDK/새 목록 API를 배포하지 않았다.

다음은 원 계산 자원을 확보한 뒤 **동일 source의 남은 빌드만** 검증하는 것이다.
통과하면 SDK 자식을 수용하고 12ui-design으로 기존 농장 목록→저장 결과 선택→기존3D/수확 화면을 연결한다.
현재 계산 상태/확정 checkpoint 자동 갱신은 계획의 U3이며 그 수용 전에는 실시간 연동으로 표시하지 않는다.
새 화면/브라우저/WebGL·제품 CLI 호출0, 실제 품종/농장 Run·국내 독립 자료0건과 기존 관문 보류를 유지한다.
