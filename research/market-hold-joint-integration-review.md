The review identified that `MarketScenarioService._prepare` did not pass the four signed context fields required by `resolve_market_context`. It recommended preserving request and baseline schemas, loading the independently signed DecisionContext from a trusted server repository, and comparing tenant, D, snapshot, context ID, claim mode and decision time kind before use. Our code inspection found the same resolver is also called directly by `EconomicLedger.calculate`; a change only in the market scenario service would leave the ledger blocked. The implementation therefore performs the signed lookup and equality checks inside the shared resolver for every context-bearing report. Caller-supplied expected fields remain optional comparisons and cannot replace the signed lookup. Missing signed context, revoked scope, changed report scope, or mismatched identity fails closed.

The [integration test](../backend/tests/test_market_signed_hold_integration.py) uses synthetic keys and a test authority. Its baseline, shock, rights and settlement records remain in a test-owned memory repository. It proves only that the signed hold and candidate replay software paths connect; it does not prove a production planning event, market G0, an approved MarketSnapshot, forecast, crop ranking, or deployed DB roles.
