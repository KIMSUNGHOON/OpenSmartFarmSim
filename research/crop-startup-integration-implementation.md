## 통과한 검증과 자원 한도

- 모듈이 없을 때 RED import 실패 후 구현했다. 첫 GREEN은 46개/25.50초이며
  추가 경계 검증까지 포함한 최종 새 시험은 **56개**다.
- 기존 모든 작물 계산 회귀 포함 **678개/32.69초·건너뜀 0개**를 통과했다.
  실제 새 56개 수집 목록과 각 시험/생성/자원 로그 hash를 보존했다.
- 제품과 독립적인 70자리 Decimal의 **6프로그램/23시점·2,829개 수치**를
  같은 적분 간격으로 대사했다. 최대 비영 상대 차이는 **7.538427e−15**다.
- 첫 명시적 유입/무진입/첫 구획/전량 제거 후 재유입·day/night/RGR 변화·초기/끝 사건과
  기존 양의 tail 2프로그램의 상태·기존 누적량 동등성을 확인했다.
- 독립 선형 개수 이동 해석해의 **550개 N 값**, 정확한 Tsum/온도 필터,
  누적 진단 변조·양의 RK4/누적 호흡 underflow·overflow와 단위/shape/UTC/예산을 검사했다.
  실패는 phase/reason·확인된 과거 sample/last_confirmed만 반환한다.
- 입력 snapshot/caller 변경 격리·동일 재현·코드/profile/정책/입력/result hash와
  reference 생성 2회의 byte-identical 결과를 확인했다.
- 합성 무진입 24시간/512출력은 **1,022 step·7.947142초·최대 43.36 MiB**로 완료했다.
  결과는 **3,474,577 bytes**이며 네 수지·512개의 빈 N/C를 모두 확인했다.
  24시간 일정 광 조건의 소프트웨어 자원 시험이며 실제 기상/작기나 브라우저 시험이 아니다.
- 단일 `nice -n 10` 과정으로 순차 수행했다. 의존성·DB/상주 서버를 추가하지 않았다.
  정확성/단위·입력 보안·기존 bytes 보존·의존성 방향·고정 자원 비용을 검토했다.

새 모델의 DB/TLS/브라우저 경로와 전체 hosted CI는 이번 단계에서 수행/수용하지 않았다.

part4/5 대기 상태를 확인했다. 그 SHA에는 이 새 적분/기관 모듈이 없다.

## 관측 오차와 적용 한계

0.25초 독립 참조 대비 마지막 buffer의 최대 절대 오차(`mg_CH2O/m2_floor`)다.

| 프로그램 | 8초 | 4초 | 2초 | 1초 |
|---|---:|---:|---:|---:|
| 빈 초기 첫 유입 | 0.770554 | 0.372847 | 0.173995 | 0.0745693 |
| 전량 제거 후 재유입 | 0.770679 | 0.372909 | 0.174024 | 0.0745817 |

전환 오차는 줄지만 약 2배 수준이며 4차 수렴으로 표현하지 않는다.
별도 매끄러운 야간 사례의 120/60/30초 오차는
4.418024e−6 / 2.836924e−7 / 1.775959e−8로 약 15.57/15.97배 줄었다.
미검증 프로그램의 수렴은 manifest에서 계속 `not_evaluated_for_this_program`이다.

개수 해석해 대비 전체 N의 상대 L1 차이는 첫 유입/첫 구획 사례에서 약 1.16e−16/1.79e−16이다.
하지만 극히 작은 개별 tail N의 상대 차이는 각각 **최대 약 8.52%/7.80%**다.
각 구획 오차도 증거에 기록했으며 합계 보존을 모든 미세 구획 정확도로 확대하지 않는다.
양의 tail이면 크기와 무관하게 요청 전체를 실현하는 기존 정책은 검증된 총 sink 용량이 아니다.
초기 유보 누적량도 간격에 민감하다. 이 값을 실제 착과·생산 정확도/농장 예측으로 게시하지 않는다.
