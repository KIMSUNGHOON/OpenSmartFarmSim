# 저장된 잎 면적과 토마토 3D의 첫 연결

상태: R3a v1 소프트웨어 / R3b 실제 저장 cycle 연결 수용, 2026-10-21. 사용자는 앞선 외형 확인본의 방향을 선호했고 계속 진행하도록 지시했다.
R3a는 기존 v1 기관 탄소 연구 조회의 전체 저장 시계열이다.
긴 cycle의 페이지 연결은 아래 R3b이며 공동 기후/환기·과실 표현·품종 형태 모델과 자동 작물 선정은 후속이다.

## 판단과 연결 계약

현재 native Codex CLI의 2026-10-21T09:45:03.797Z context에서 `gpt-6.1-sol`/`xhigh`를 확인했다.
context 원 line SHA-256=`38906c01e78a1fc4ebf279c994d7c4bc13810cfeaee855e8c46373d87c098f11`.
이 세션에서 판단·코드·시험을 수행하며 재귀 CLI를 실행하지 않는다.

[기존 API v1](../contracts/api-crop-replay-v1.md)의 완료 sample은 LAI와 기관 탄소량을 제공하지만
키·기관별 위치/잎 수·과실 크기/색·숙기를 제공하지 않는다. 이 부재는 현재 계약/코드에서 확인한 사실이다.
LAI 하나가 특정 식물 형태를 유일하게 정하지 않는다는 것은 이번 설계 판단이며, 새로운 생물 계수를 채택하지 않았다.

`stored-lai-relative-area-v1`은 이미 SDK가 검증한 **같은 전체 v1 결과**의 최대 LAI를 고정 표시 기준으로 삼는다.
선택 sample의 `LAI / 최대 LAI`만큼 직접 제작한 잎들의 삼각형 표면적이 변한다.
각 잎의 시작점·개수와 줄기 구조는 고정 외형 가정이다. 길이 배율은 이 면적 비율의 제곱근이며 생장 방정식이 아니다.
표시 기준은 이 사후 저장 재생의 레이아웃 정규화다. 미래 예측 입력/작물 계수나 실제 m² 형상의 보정으로 사용하지 않는다.
모든 LAI가0이면 잎을 숨기고 0/0을 만들지 않는다. 실제 작은 변화는 그대로 작게 표시한다.

선택 result ID/UTC·원 LAI·결과 payload hash는 원값을 보존한다.
3D GPU 갱신 뒤 실제 instance matrix의 삼각형 면적을 대사해 연결 증거를 남긴다.
과실/꽃받침/꽃과 반복 배경 식물은 이 모드에서 숨긴다. 고정 외형의 과실을 계산된 수확처럼 표시하지 않는다.
범위 밖 index·수치 hold·음수/비유한 LAI는 연결 보류다. 조회 실패·현재 권리/계정 변경 시 기존 부모가 결과를 지우고
3D도 해제한다. 보류 때 대표 외형으로 바꿔 정상 계산처럼 보여 주지 않는다.

기존 조회 화면의 `토마토 잎 면적 3D` 버튼으로 진입한다. 기본 모식도 경로와 기존 수치 검증은 유지하고
동일 slider/표/그래프가 같은 선택 상태를 전달한다. 별도 API·worker·모델 출력 필드는 추가하지 않는다.
사용자가 선호한 기존 외형·조작 디자인을 재사용하고 CSS는 해당 컴포넌트 안으로 제한했다.

## 소스·권리

- [Three.js InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html), 2026-10-21 조회:
  instance matrix 갱신 통지, bounding sphere 재계산과 자원 해제 절차를 확인했다.
- 기존 저장 API 계약/현재 `CropReplay` SDK와 앞선 직접 제작 외형/표면을 사용한다.
  외부 농업 매개변수·사진·3D 자산을 새로 채택하지 않았다. 코드/표면의 기존 Apache-2.0,
  Three.js MIT와 폰트 OFL 고지를 유지한다.
- 식물 구조 논문의 검색 결과는 검토 후보로만 보았고 PMC 본문은 접근 검사로 열리지 않았다.
  그 논문의 계수·정확도·이미지를 이번 모델/품종 근거로 채택하지 않았다.

## 검증 계획과 관측

native Windows Node에서 같은 기하 검사를 실행해, 구현 전 `setLeafAreaRatio` 부재로 실패한 RED와
구현 후 실제 삼각형 면적 1/4·0·복원/잘못된 비율 거부·과실 숨김의 GREEN을 확인했다.
Windows Node RSS 관측은85,454,848bytes이며 WSL 공통 용량 수용이 아니다.

hosted에서는 타입·기하/연결 단위 검사, 기존 독립 외형 3검사와 기존 고정 앱에 작은 패치만 적용한 빌드를 검사한다.
빌드된 앱에서 v1 원 UTC/LAI·payload hash·삼각형 면적비·표/그래프·과실 보류와 현재 조회 거부 시 제거를 확인한다.
기존 조회/메뉴 이동 회귀도 함께 확인한다. 원본 앱은 기존 고정 source에 네 군데만 추가하며
그 외 미수용 앱 기능이나 새 물리 모델을 배포하지 않는다.

**남은 의존성:** 해당 실제 저장 v1 결과의 현재 조회/사용자 적용, 다른 family의 고정 표시 기준,
품종/시기별 형태 근거·권리, 기관별 발달 모델과 G0–G4의 기존 관문.
cycle의 표시 기준과 실제 사용자 적용은 아래 R3b에서 수용했으며 공동 기후/환기 family는 남는다.
이 연결은 합성 저장 수치의 표시 계약이며 실제 농장 성장·생과 수확·추천의 검증이 아니다.

## R3a 소프트웨어 수용과 R3b의 착수

[source2863369 / CI39582186631](https://github.com/KIMSUNGHOON/OpenSmartFarmSim/actions/runs/39582186631)의
현재8단위/외형3브라우저·타입/빌드/audit0, 고정 앱57단위/빌드된 앱19브라우저를 확인했다.
원 v1의 LAI·UTC/payload hash·실제 표면적비와 과실 숨김, 표/그래프와 조회 거부 시 제거,
기존 모식도/연결/메뉴 유지가 통과했다. 첫 CI39581702543은 이전 crop 브라우저 시험이
이미 열린 연결 폼을 닫아서 실패했다. 현재 공통 연결 helper를 쓰는 시험으로 맞춰 수용했다.

실제 사용자 미리보기는 v1 저장소 대신 계산 검토 cycle/수확 조회를 조립한다.
따라서 v1 시험을 실제 긴 작기의 연결 완료로 보고하지 않는다. 실제 현재 API에서 요약·최초·마지막
47,809시점의 저장 결과를 각각 조회해200과 같은 불변 reference를 확인했고 마지막 LAI가 양수임을 확인했다.
세 읽기는 약8.14/7.64/7.33초였으며 모델 재계산을 요청하지 않았다. 개인 식별자/토큰/원문은 private에 보존했다.

R3b는 기존 cycle의 `seekSample`로 마지막 **실제 저장 시점**을 먼저 조회해 표시 기준을 고정한다.
첫 연결은 그 시점으로 이동한다고 화면에서 설명한다. 이후 다른 페이지로 이동해도 그 result/payload·마지막 LAI/UTC를 유지한다.
기존 창의 단일 요청·중단/현재 권리 검사를 그대로 쓰며 별도의 동시 API 요청이나 전체 작기 다운로드를 만들지 않는다.
이 기준은 최대 LAI라는 주장이 아니다. 선택 LAI가 기준보다 크거나 기준이0이면 그림 표시만 보류하고 원값은 유지한다.
키·기관 개수/배치·숙기·수확을 추정하지 않으며 과실/꽃·배경 식물은 숨긴다. 같은 G0–G4 범위를 유지한다.
이 endpoint 기준의 순수 계약도 구현 전 부재 RED와 구현 후 GREEN을 native Windows Node에서 확인했다.
처음 두 native 실행기의 경로/TS 변환 문제는 계약 RED로 세지 않았다.

## R3b 수용과 사용자 적용

[source42d5284 / CI39584108997](https://github.com/KIMSUNGHOON/OpenSmartFarmSim/actions/runs/39584108997)의
현재12단위·독립 외형3브라우저, 기존5174 기준61단위/빌드된21브라우저와
실제 legacy source7ff954b 기준80단위/빌드된13브라우저가 통과했다. 타입·두 고정 앱/외형 빌드·audit0도 확인했다.
이 수치는 겹치는 검사를 포함하므로 합산한 고유 전체 회귀나 새 물리 모델 검증으로 보고하지 않는다.
최종 legacy ZIP의 제공된 SHA-256 digest를 확인하고, 원 App은 그대로 둔 채 v1 부모 네 군데와
같은 원 CycleCropReplay의 표시 기능만 추가한 출처/원 코드 hash를 대사했다.

실제5173은 이 legacy 빌드로 교체했다. 기존 개발 진행 안내를 가진 HTML의 entry JS/CSS 두 참조를 갱신하고
NGINX의 정적 root/HTML alias만 바꿨다. 같은 master의 pidfd reload와168개 빌드 파일/원164개 frontend 보존,
새 compiled asset의 HTTP/hash를 확인했다. 원 backend/모델·DB·키/토큰과5174/5175는 교체하지 않았다.
첫 적용 전 검사는 source-hash dictionary의 상대 경로를 잘못 읽어 중단했고 runtime 수정 전에 바로잡았다.

전용 Windows Chrome에서 **mock 없이 현재 API**를 연결해 마지막→최초→실제 저장 시점 자동 재생→마지막을 조작했다.
요약1+시점 페이지4=GET5개는 모두200이며 새 계산 POST0·JavaScript 오류0이었다.
원47,809시점 중 처음/마지막의 raw LAI·payload hash/UTC와 표/그래프·실제 삼각형 면적비가 일치한다.
첫 LAI2.659734, 마지막8.972676029873755의 면적 비율을 그대로 사용했다. 날짜는 합성 모델의 시계이며 미래 현장 예측이 아니다.
실제 화면: [처음](artifacts/tomato-stored-native-first-20261021.png),
[마지막](artifacts/tomato-stored-native-last-20261021.png). [공개 증거](artifacts/tomato-stored-leaf-area-20261021.json)에 원 source/화면 hash를 보존했다.

첫 두 native는 Playwright 이벤트가 전달된 시점만 센 동시성2 때문에 미수용했다.
최종 관측은 원 지표2를 그대로 보존하고 브라우저 본문 소비의 peak1과
[CDP Network 사건](https://chromedevtools.github.io/devtools-protocol/tot/Network/)의 내부 monotonic timestamp peak1을 따로 확인했다.
실제 요청 구간은 겹치지 않았으며 최소 간격은 약2.779ms였다. [Playwright 사건](https://playwright.dev/docs/api/class-page#page-event-requestfinished)의
전달 시점 계수를 실제 네트워크 겹침으로 사용하지 않았다. 제품 코드를 바꾸거나 단일 조회 조건을 낮추지 않았다.

최종 native는40.442초·.25초157관측으로 WSL 합산 peak899,768,320bytes/PID132,161,536bytes,
기존6root 생존/보류 없음이었다. Windows Chrome/Node 메모리는 제외하므로 공통 전체 용량 수용은 아니다.
화면은 사용자가 볼 수 있게 남겼고 원 자료와 이전 정적 빌드를 보존했다. 복구/현재 HTML 검사는 private handoff의 새 root/entry를 따른다.
같은 작업의 중복 탭2개만 닫고 최종5173 화면·기존5174와 독립5175를 유지했다.
진행 안내를 두 포트에 게시해 HTTP200/동일 bytes/no-store와 실제 HTML을 확인했고
동결 환기 source2,173파일의 원 hash도 대사했다. 이 문구 갱신에 브라우저 시험을 반복하지 않았다.

**이 단계의 완료 범위는 저장된 합성 LAI를 외형에 연결한 재생이다.** 실제 키·기관 개수/배치·개화/착과·과실 크기/색·숙기·생과 수확과
그 결과의 자원/경제·자율 작물 선정은 다음 작업이며 G0–G4를 통과한 것으로 표시하지 않는다.
