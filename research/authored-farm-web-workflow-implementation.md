# 작성 농장 웹 작업 연결: 합성 소프트웨어 검증

확인일: 2026-09-30. 이 기록은 이미 등록된 작성 농장 판본을 내부 웹에서 검토 접수, 열 계산 접수, 저장 Run 3D 재생으로 연결한 소프트웨어 후보의 증거다. 농장 수치의 타당성이나 G1 통과 기록이 아니다.

## 구현 범위

- 사용자는 서버가 발급한 `scenario_id`와 `scenario_revision`으로 등록 요약을 조회한다. 서버가 반환한 등록·농장·경제·권리 해시와 입력 작업 ID를 표시한다. 원본 농장 입력이나 권리 선언은 요약 응답에 포함되지 않는다.
- 검토 접수는 등록 해시에 고정된 요청과 메모리의 멱등 키를 사용한다. 실제 작업의 완료나 `hold`는 서버 상태/보류 조회로만 표시한다.
- 계산 접수는 검토 작업의 완료 뒤에만 활성화한다. 서버는 별도의 현재 독립 서명 해제와 권리·입력을 다시 확인한다. 요청이 보류되면 3D 링크는 활성화되지 않는다.
- 완료된 작성 열 작업 ID를 기존 저장 Run 조회 화면으로 전달한다. 사용자가 **저장된 Run 조회**를 누르면 기존 장면·그래프·표가 서버의 120개 저장 시점을 읽는다. 작업 단계 화면 자체는 계산값을 생성하지 않는다.

## 확인 절차와 결과

- `cd web && npm run typecheck`: 통과.
- `cd web && npm run test`: 71개 통과, 7개 파일. 새 API 계약 시험 3개 포함.
- `cd web && npm run build`: 통과. 기존 큰 번들 경고는 남음.
- `cd web && OSSF_TEST_WEB_PORT=5174 npm run test:browser`: Chromium 22개 통과. 새 시험 2개는 합성 HTTP 응답으로 등록 조회 → 검토 → 계산 → 작성 Run 3D 이동과 해제 누락 422/동일 멱등 키 재요청을 확인했다. 5174는 로컬 3D 데모(5173)를 유지하면서 시험한 포트다.
- 실제 Chromium 캡처: [데스크톱](artifacts/authored-workflow-desktop.png), [휴대전화](artifacts/authored-workflow-phone.png). 두 이미지의 ID와 상태는 시험용 합성 응답이다.

## 남은 수용 조건

검토·계산 작업의 새로고침 후 복구 경로는 아직 없다. 선행 조사·원본·시장 보류·경제 입력 발급은 기존 서비스/API 또는 운영자 절차로 먼저 해야 한다. 위 합성 HTTP 브라우저 시험은 실제 PostgreSQL, 독립 검토자, 실제 Codex CLI 실행을 사용하지 않았다. 별도의 [합성 서비스·브라우저 연결 시험](authored-full-software-path-implementation.md)은 실제 PostgreSQL/SCRAM과 HTTPS에서 등록 조회, 신규 검토·계산 작업의 브라우저 접수와 하네스 작업자 완료, 저장 Run 3D를 확인했다. 그 시험의 CLI와 해제 권한은 합성 fixture다. 두 접수 POST의 180초 브라우저 제한은 관측한 지연에 대한 임시 조치로, 운영 지연 수용은 보류다. 실제 CLI `gpt-6-sol`/`xhigh` 검토·출력 기록과 독립 해제, 재실행·복구, 권리·자료 확인이 갖춰질 때까지 `end-to-end-g1`, `web-shell`, `web-replay` 수용 체크와 G1은 보류한다. 생장·수확·구매 에너지·미래 마진·작물 순위는 이 화면의 출력이 아니다.

## 마지막 판본 재확인 후보 (2026-09-30)

조회에 성공한 마지막 판본의 시나리오 ID·판본·등록 해시만 브라우저 탭의
`sessionStorage`에 보관한다. 새로고침 후 접근 토큰을 다시 입력하면 서버의
기존 인증 GET으로 현재 권한·근거를 재확인하고, 등록 해시까지 일치할 때만
화면에 복원한다. 토큰·농장 원문·검토/계산 작업 ID는 저장하지 않는다.
접근 거부·판본 없음·해시 변경은 저장한 선택을 지우고 결과를 표시하지 않는다.
일시적인 통신 실패는 ID만 남겨 수동 재확인을 허용한다.

`npm run typecheck`, `npm run test`(**71 passed**), `npm run build`와
`OSSF_TEST_WEB_PORT=5174 npx playwright test e2e/authored-workflow.spec.ts`
(**3 passed**)를 확인했다. 브라우저 시험은 새로고침·재연결 성공,
해시 불일치와 접근권 철회의 복원 거부, 세션 저장소의 토큰 부재를 확인한다.
이는 마지막으로 조회한 판본 **한 건**의 같은 탭 재확인이다. 서버의
사용자별 판본 목록, 다른 기기 접근, 접수 키/작업 재개, 실제 제품 인증은
여전히 구현되지 않았다.

## 직접 작성한 농장 판본 등록 후보 (2026-09-30)

`04 작성 농장 실행`의 새 입력 화면에서 조사 작업 UUID, 원본 열 스냅샷,
결정 문맥, 시장 보류 보고서, 경제 시나리오·후보 해시를 명시적으로 입력한다.
시설·초기 상태·난방·구간별 강제 조건과 선택적인 재배 달력/등급·판매 경로도
모두 사용자 가정으로 입력한다. 수치의 단위는 고정하며 지수 표기나 빈 값을
새 수치로 바꾸지 않는다. 입력 구간과 원본 구간, 경제 배치/날짜, 권리와 판본은
서버가 현재 기록으로 재검사한다. 화면은 농업 계수, 기상, 작물 출력, 실제
에너지 구매량이나 경제 전망을 생성하지 않는다. 시장 문맥은 `unavailable`이다.

제출 전에 기간·구간 수·작물 의도 수·시장 보류·권리 범위를 보여준다. 응답
유실 시 입력을 잠그고 동일한 요청 바이트로 재확인한다. 성공하면 등록 요약의
ID·판본·해시만 탭 세션에 저장하고 기존 검토 작업으로 이어진다. 폼 원문과
접근 토큰은 저장하지 않는다. 브라우저에 표시된 권리 체크는 사용자 선언이며
G0 승인·독립 검증이 아니다.

`npm run typecheck`, `npm run test -- --run` (**73 passed / 8 files**),
`npm run build`가 통과했다. `OSSF_TEST_WEB_PORT=5187 npx --no-install playwright test
e2e/authored-form.spec.ts e2e/authored-workflow.spec.ts`는 **4 passed**였고,
첫 POST를 중단한 뒤 같은 바이트의 POST 재전송, 등록 후 요약·세션 식별자만
보관, 휴대전화 가로 넘침 없음과 기존 작업 회귀를 확인했다. 합성 POST 요청은
서버 Pydantic `FarmAuthoringRequest` 스키마도 통과했다. 이 결과는 실제 DB
등록 성공을 뜻하지 않는다. 실제 SCRAM/HTTPS/Chromium 전체 경로 시험은
CI에서 별도로 확인한다. 일반 사용자가 지역만 고르면 끝나는 화면은 아직 아니다.
