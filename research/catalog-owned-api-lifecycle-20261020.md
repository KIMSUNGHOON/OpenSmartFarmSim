## 수용 범위

지원하는 **원 저장 판본 reader의 별도 API**에서 현재 입력 권리 철회/복원과 실제 프로세스
재시작을 수용했다. 원 합성 dump를 독립 PostgreSQL 16.15에 복원했다. 원 사용자 API/DB는
재시작하지 않았다. 원 결과·입력·서명을 다시 만들지 않았고 계산/발급/게시 호출은0이었다.
브라우저 검증과 사용자 적용·전체 U1 및 G0–G4 수용은 아니다.

현재 native Codex CLI `gpt-6.1-sol / xhigh`에서 조사·판단했다. 실제 문맥과 원행 해시,
원 실행기 두 파일의 해시는 기계 증거에 기록했다. 재귀 CLI/하위 에이전트 호출은0이다.

## 실제 관측

SCRAM을 사용하는 같은 소유 DB/HTTPS 주소·CA·계정에서 아래5조회씩을 수행했다.
대상은 저장 목록, 생장 요약/7시점, 수확 요약/3행이다.

| 상태 | 실제 HTTP | 원 응답 대사 |
| --- | --- | --- |
| API A·권리 true | 200×5 | 기준 원 bytes/hash |
| 같은 A·소유 권리 false | 422×5 | 원 reader의 실제 현재 권리 거부 |
| 같은 A·권리 true 복원 | 200×5 | 기준5개와 각각 bytes/hash 일치 |
| A 종료·listener 폐쇄 뒤 B | 200×5 | 다른 PID/start identity, 기준5개와 각각 일치 |

합20응답·가장 긴 관측11.858621초였다. socket timeout30초를 설정했으나 전체 wall deadline을
강제하는 실행기는 아니므로 일반적인30초 응답 보장을 수용하지 않는다.
양 API의 DB counts·원 생장 record가 불변이었고 정상 종료0/FD4를 확인했다.
복원 PG는 종료하고 data 디렉터리를 제거했다.

소유 guard는 종료0·147.403284초, 단일144,240,640/합872,775,680bytes였다.
원512MiB/PID·합1GiB/600초/.25초 표본을 유지했다. 원5root와 하위 프로세스,
원본2148개·두 frozen 사용자 화면/자산을 보존했다. 시험 소유 프로세스/PG 잔여0이었다.
별도 private 실행 디렉터리에 남았던5시도의 복사 자격증명·제어 파일58개도 종료 확인 뒤
제거하고 경로별 부재를 다시 확인했다. 원 참조 파일은 제거하지 않았다.

## 기각한 공유 DB 후보

초기 후보는 보호 DB를 읽기 전용으로 공유하려 했다. 환경 `PGOPTIONS`는 명시 연결 옵션에
덮여 실제 readonly가 off였으므로 노출 전 중단했다. 연결의 실제 readonly를 on으로 만든
후속 조회는 `ReadOnlySqlTransaction`/SQLSTATE25006과422로 거부됐다. 진단은 오류 종류를
관측했으며 정확한 실패 SQL을 수집하지 않았다. 기존 reader의 행 잠금/거래 검사를
생략하거나 보호 DB에 쓰기 가능 시험을 하는 대신 독립 복원 DB로 전환했다.
