## 실제 CLI와 고정 계산

현재 CLI `01a0e064-b01b-7a22-8ef8-dd4afe0eb7dc`의 실제 turn_context
`2026-10-05T00:27:12.101Z`에서 **gpt-6.1-sol / xhigh**를 확인했다.
이 세션에서 설계/계산 판단과 구현을 수행했고 CLI를 재귀 실행하지 않았다.
실제 turn hash·코드 출력 hash는 증거에 기록했다. 별도 제품 runtime CLI 수용은 아니다.

새 `explicit-entry-empty-sink-plant-rates-research-v1`은 기존 기관 kernel의 요청 Fq를
시작 adapter에 전달한다. 빈 tail에서는 S×W1=Fa만 과실로 보내고 R=Fq−Fa를 유보한다.
buffer 미분에 `(1+cG)×R`를 더하고 과실 생장 호흡을 `cG×Fa`로 동시에 바꾼다.
잎/줄기 계산은 유지하고, 과실 미분/유지 호흡은 50구획에서 한 번만 사용한다.
R을 잎·줄기·과실로 다시 배분하지 않는다.

기존 v1의 모듈 bytes/모델/적분/결과를 수정하지 않았다.
기존 닫힌 block 검사를 재사용하고 public 구획 수요 검증 뒤 C 합계에서 과실 총량을 파생한다.
shared 온도·고정 profile 대응·입력/정규화/정책·component hash를 검사/기록한다.
잎/줄기의 fixed RGR는 연구 가정으로 계속 출력한다.
요청과 실현 allocation을 별도 필드에 표시하며 전체 탄소/개수 잔차와 예산을 반환한다.

## 실제 검증과 검토

- 제품 모듈이 없을 때 import 실패를 기록한 뒤 구현했다. 최초 repository-root 시험의
  module 경로 오류도 별도 로그에 보존하고 올바른 backend cwd에서 다시 수행했다.
- 새 **78개/0.27초**, 기존 모든 작물 회귀 포함 **622개/6.99초·건너뜀 0개**를 통과했다.
- 제품과 독립적인 70자리 Decimal의 **22사례/4,796개 수치**를 대사했다.
  17/20/23°C·기존 6사례·빈 배열/진입/무진입·첫 구획·0 buffer·1e−200/1e200
  배열 크기·공급 RGR/구획 유지 호흡·LAI/기관·50개 이동/배분/개수/탄소를 확인했다.
  비영 값의 최대 상대 차이는 3.95721e-15이며 0 참조 2344개도 정확히 일치했다.
  비교에는 작은 값을 숨기는 절대 tolerance 바닥을 두지 않았다.
- 원 v1의 양의 tail 6사례는 기관/구획/호흡/배분 등의 값과 구조까지 동일하다.
  빈 tail의 균형 진입도 원 판본과 동일하며 임의 seed가 생성되지 않는다.
- buffer만 보정하거나 호흡만 변경한 두 결함을 거부했다.
  단위/닫힌 입력/범위/공유 온도·진입 예산/양의 곱 underflow·배열/유지 호흡/합계
  overflow와 C>0⇒N>0·원 광합성 영역 hold를 확인했다.
- 참조 생성 2회는 byte-identical이고 원천/코드/profile/정책/hash를 고정했다.
  입력 불변·동일 재현·provenance가 다른 요청의 hash 차이를 검사했다.
- 정확성/입력 보안/기존 판본 보존/의존성 방향/고정 50구획의 제한된 비용을 검토했다.
  새 의존성·상주 서비스·DB/브라우저 작업은 추가하지 않았다.
  변경 Markdown 8파일의 로컬 링크 710개와 증거의 코드/참조 pin 17개도 확인했다.

현재의 독립 식 비교·숫자 범위는 합성 소프트웨어 검증이다.
DB/브라우저 전체 경로를 재실행하지 않았고 새 모델의 hosted CI·적분/저장/3D는 미수용이다.
