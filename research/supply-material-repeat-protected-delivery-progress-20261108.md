# 반복 material 보호 전달 — backend 구현의 중간 진행

[strict client 라이브러리](supply-material-repeat-client-library-20261108.md) 뒤에 고정 root의 manifest/Frame GET을 구현했다. [출처·검사 범위](artifacts/supply-material-repeat-protected-delivery-progress-20261108.json)는 앞선 core4개/3명령, mixed 명령의 별도 D1개, 수정 TLS+ownership E2개다. 현재7개 함수의 개별 통과 근거를5개 실제 명령 판본에 대사했으며, 그중1명령은 TLS 실패/D 통과였다. 전체7개의 한 명령 통과나 보호 전달 부모의 수용은 아니다.

실제 first13 합성 artifact의 원 manifest, 같은 At/다른 basis의 Frame0/1·dense null/confirmed를 원 물리 bytes/hash/길이와 대사했다. 하나의 불변 registry에서 인증/테넌트/각 scope 거부9행은 추가 public reader 진입0, 입력·메서드/경로 오류10행도 진입0이었다. admitted index2는 실제 전체 재구성 뒤422로 보류했고 정상 Frame 재시도를 확인했다.9/10행은 별도 pytest 개수나 모든 metadata I/O0이 아니다. fixture setup은 실제 수치/게시 작업을 포함한다.

원 reader60과 전체 source/권리/code/storage 검증은 유지했다. 새 adapter30은 기존 외부 인증을 거친 FastAPI 진입부터 시작하며 전체 HTTP30의 증거가 아니다. 콜 시간은 여러 실제 읽기·inventory·assertion을 포함하므로 단일 HTTP 지연으로 사용하지 않는다. 앞선4개와 D/E는 직접 ASGI 범위이며, 아래 TLS 두 GET만 실제 SSL로 별도 확인했다. 실제 경과 expiry·source/code/policy 변경 및 전체 전달 수용으로 확대하지 않는다.

[전달 계약](../contracts/supply-material-repeat-protected-delivery-v1.md)은 구현 전 동결한 규범 제안 판본을 그대로 보존했다. 그 문두의 당시 pending/no-implementation 상태와 현재 구현 진행을 구별하며, 규범을 바꾸거나 과거 검사 지문을 새 판본으로 재명명하지 않는다. 전체 전달 구현·수용은 여전히 보류다. 뒤에 붙은 시험은 앞선4개 근거에 섞지 않고 각각 실제로 실행한 판본과 범위로 대사한다.

이후 후속 TLS/expiry 두 case를 함께 실행한 명령은 TLS의 최종 자식 FD 정확 일치 검사에서5 대6으로 실패했다. 최종 TLS metrics와 그 뒤 inventory/source 확인은 도달하지 못했고 원인도 아직 확인하지 않았다. 같은 명령의 별도 expiry case는 실제 읽기의 정상 반환·FD 정리 뒤 두 경계의 인증 재검사를 통과했다. 이는 registry가 지원하는 UTC clock 값의 제어이며 실제 경과시간/TLS expiry가 아니다. 이 mixed 결과를 앞선4개 checkpoint의 통과 수에 합치지 않는다. 기존 core4 checkpoint와 현재7함수 판본을 구분하며, 후속 mixed 명령을 통과 suite로 게시하지 않는다.

수정 TLS는 진짜 server를 한 번 구성한 뒤 thread 시작부터 client/reader·drain/join까지 측정했다. 실제 검증 TLS의 manifest와 Frame0 전신 수신·EOF는 각각10.73초/10.60초로 독립 GET30 안에 완료했다. 미완성 body는 실제30초 timeout, 두 실제 reader 정상 반환과13개 명명 경계/26개 진입 전 제어, 구성 후 FD5→5·inventory/source 보존을 확인했다. 이 범위는 생성자/전역 logging handler 보존이 아니며, 현재 실행에서 관측한 handler 정리는 과거 실패의 소유자나 제품 결함 수정을 소급 증명하지 않는다. 두 GET의 선택 전체30이나 full14/다른 Frame 지연을 뜻하지 않는다.

E는 실제 reader의 열린 FD와 소유 event를 관측해 취소 요청 뒤에도 정리가 끝나기 전에 요청이 종료되지 않음을 확인했다. 정상 raw 반환/FD 정리 뒤 Task.cancel 전파 또는 ASGI disconnect 무응답, 새 정상 재시도를 통과했다. 실제 TCP/TLS 연결 중단 증거는 아니다.

후속은 실제 경과 expiry/source/code/policy 변경, full14/all10 보호 전달·raw TS transport/동일 출처 proxy다. 첫2Frame 결과를 선택 예정인 full14/10Frame에 외삽하지 않고, 비공개 기존 full artifact의 실제 전달을 따로 확인한 뒤 같은 선택의 metric3D/표·그래프/브라우저로 진행한다. use/display=true·redistribute=false, 원 모델/자료·이전 수집 HOLD/feature RED를 보존하며 public raw/token 복사를 만들지 않았다. Farm/작기/비용·G0–G4/R2·hosted CI·전체 client/goal은 미수용·미완료다.
