# 명시적 빈 과실 sink의 순간 요청/실현 계산

날짜: 2026-10-05 KST. **순수 순간 연구 소프트웨어 로컬 수용**이다.
[계약](../contracts/crop-fruit-startup-rates-v1.md),
[정책 조사/외부 보류](crop-fruit-startup-policy.md),
[실제 출력/해시/시험 로그 증거](artifacts/crop-fruit-startup-rates-reference-20261005.json)를 함께 읽는다.
현재 CLI `gpt-6.1-sol` / `xhigh`에서 직접 구현했다. 세션/실제 turn과 재귀 호출 없음은 증거에 기록했다.

## 바뀐 계산과 보존

`backend/app/crop_fruit_startup.py`는 명시적 S/W1·50개 잠재 수요와 고정 구획 profile을 받는다.
빈 tail에서는 S×W1만 실현하고 나머지 요청을 유보한다.
실현된 과실 구조 탄소에만 생장 호흡을 붙이고, 후속 기관 계산에 필요한
buffer 미분 보정 `(1+cG)×R`를 별도로 반환한다. 기존 배분/기관/적분 코드를 변경하지 않았다.

예를 들어 **직접 작성한 합성 사례** Fq=10, S=2, W1=1에서 빈 sink의 Fa=2,
R=8, 기존 일반 참조 cG=0.27의 실제 구조 생장 호흡=0.54,
buffer 보정=10.16이다. 탄소 유량 단위는 모두 mg_CH2O/m2_floor/s이며
S는 fruits_equivalent/m2_floor/s, W1은 mg_CH2O/fruit_equivalent다.
이 값은 농장 관측/실제 생산량·과중이나 경제 비용이 아니다.

tail 수요가 있거나 이미 요청과 진입이 균형이면 기존 v1의 50개 배분을 그대로 사용한다.
원 요청·정규화 입력·정책/고정 profile·내부 배분 hash를 모두 결과에 묶는다.
요청을 다르게 주고 같은 Fa가 나오는 경우에도 hash는 다르다.
유보를 buffer에 돌리고 생장 호흡을 함께 줄였을 때만 전체 탄소 수지가 성립한다.
현재 API/적분/저장/3D는 새 adapter를 호출하지 않는다.

## 통과한 검증

- 새 모듈이 없을 때 시험 수집의 `ModuleNotFoundError`를 기록한 뒤 구현했다.
- 새 **56개/0.09초**: 제품과 독립적인 70자리 Decimal의 9개 정상/5개 hold,
  900개 C/N 유입 수치, 요청/실현/유보·전체 탄소 수지·원 판본 배분 일치,
  단위/shape/범위·입력 불변/재현/hash·고정 profile을 검사했다.
- 양의 곱/호흡 underflow, tail 비율 underflow, 진입/요구 합계/buffer 보정 overflow는 hold다.
  epsilon·clip·임의 초기 과실 개수/추가 품종 계수는 없다.
- 기존 작물 유량/영역/적분·이동·배분/구획·기관/짧은 결합을 포함한
  **544개 통과/6.89초·건너뜀 0개**로 기존 488개 회귀를 확인했다.
- 실제 14개 결과(9개 출력/5개 hold), 코드/원천/profile/참조 hash와 로그 hash를 공개 증거에 보존했다.

이번에는 DB/브라우저 전체 경로를 다시 실행하지 않았다. 현재 저장/3D 코드를 바꾸지 않은
순수 계산 모듈이며 새 기관/적분 판본이 아직 없다. hosted 수용도 후속이다.
