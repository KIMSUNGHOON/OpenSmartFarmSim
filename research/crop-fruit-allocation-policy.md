## 선택한 작은 개발 경계

원 자동 착과와 W1/초기 seed는 아직 불명확하므로 추정값을 넣지 않는다.
대신 **명시적 연구 착과 S·진입 질량 W1**을 받는
`explicit-entry-fruit-allocation-research-v1`을 별도 판본으로 선택했다.
입력형 계산은 자동 착과 예측과 구분되며 실제 품종 매개변수 채택은 없다.

첫 구획 A1=S×W1과 뒤 구획의 상대 잠재 수요를 유지하고 분모를 j=2..50로
변경한다. 남은 유입 R=F−A1과 D2=sum(w2..w50)에 대해 뒤 배분은 R×w_j/D2다.
따라서 허용된 경우 합계는 A1+R=F다. 작은 epsilon이나 잔차 이동은 넣지 않는다.

다음 경계도 명시했다.

- 남은 유입 0이면 뒤 구획 0이며 빈 sink가 가능하다. F=0,S=0은 전체 유입 0이다.
- A1>F, S>0/W1=0, 남은 유입>0/빈 sink는 각각 명시적 hold다.
- 초기 N1/배열·S·W1을 자동 생성하지 않는다. 입력 origin도 G0 승인으로 바꾸지 않는다.
- 첫 구획은 진입 질량만 받는다. 기존 첫 구획의 추가 생장 수요를 보장하지 않는
  구조적 제약이며 실제 생리 정확도를 주장하지 않는다.
- 후속 구획 결합은 고정 Gompertz 계산의 w_j=N_j×GR_j를 사용한다. 임의 수요
  애니메이션/생과 과중이나 생성 문장을 입력으로 채우지 않는다.

이 정책은 탄소 유입량을 보존해 개발을 이어가는 명시적 연구 변형이다.
원 모델과 같다고 표시하거나 국내 농장 검증 없이 일반화하지 않는다.
실제 자동 착과/진입 질량이 필요하면 추가 근거/독립 초기 자료로 다른 판본을 만든다.

## 독립 대수·숫자와 남은 제품 구현

[독립 계산기](crop-fruit-allocation-reference.py)는 제품 함수를 import하지 않고
60자리 Decimal로 고정 합성 **6개 정상/4개 hold 사례**를 계산했다.
정상 사례의 **600개 구획 탄소/개수 유입**에서 합계를 각각 F와 S로 대사했다.
원 인쇄 분모와 작은 epsilon 분모는 각각 **4개 보존 반례**를 확인했다.
동일 생성 2회는 byte-identical이며 계약/등록부/생성 코드 hash를 출력에 연결했다.
이 수치 증거는 정책 산술이며 제품 pytest 통과나 생리 검증으로 보고하지 않는다.

다음 `crop-fruit-allocation-rates`는 2파일의 순수 제품 함수를 위 독립 값과
대사한다. 입력 닫힘/단위·길이/유한성·불변/hash와 hold, 실제 이진 수지/underflow를
검증한다. 이어서 `crop-fruit-cohorts`의 고정 GR·이동/유지 호흡·기관/buffer/사건
적분으로 연결한다. 이 구분은 매개변수 추정 없이 작게 검증하기 위한 코드 분해다.

개발 정책 조사/대수 수용은 2026-10-05 KST에 완료했다. 다음 순수 제품 배분은
정의된 2파일과 독립 600개 값의 범위로 **0.5~1 집중 작업일**의 잠정 작업량이다.
실제 실행 후 시간과 검증을 기록한다. 전체 과실 적분/한 작기 날짜는 처리 한도와
실제 입력·자동/관리 정책이 확보된 뒤 다시 추정한다.
국내 독립 자료는 0건이고 자동 착과·실제 생과 수확·자원/경제·G0–G4 hold는 유지한다.
