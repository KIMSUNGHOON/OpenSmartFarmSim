# 지역 조사에서 수집·검토로 이어지는 내부 웹 후보

2026-09-30. [화면 계약](../contracts/web-owned-source-workflow-v1.md)의
`02 작업과 근거` 화면에 완료된 조사 작업을 부모로 하는 원본 수집 접수,
완료 수집을 부모로 하는 수집 입력 검토 접수, 두 작업의 실제 서버 상태와
검토 보류 보고서 조회를 연결했다. [기존 인증 HTTP 계약](../contracts/api-owned-collection-v1.md)을
사용하며 서버의 출처·권리·문맥 재검사를 우회하지 않는다.

응답 유실 때 각 단계의 같은 입력·멱등 키를 유지한다. 페이지 안의 화면
이동은 작업 상태를 보존하고 연결 계정 또는 조사 작업이 바뀌면 지운다.
전체 새로고침 후 수집·검토 이력 복구, 자동 단계 진행, 작성 농장 입력의
필요 참조 자동 발급은 아직 없다.

이 시험은 합성 HTTP 응답의 브라우저 흐름이다. 실제 Codex CLI
`gpt-6-sol`/`xhigh` 실행, 독립 출처 승인·서명 해제, 현장 G2와
G1 종단 간 경로가 아니다. 수집이나 검토 완료를 G0로 표시하지 않는다.

검증 결과:

```text
web/ npm run typecheck && npm run test && npm run build
  typecheck passed; 76 passed / 8 files; build passed

web/ OSSF_TEST_WEB_PORT=5174 npm run test:browser
  27 passed in 50.0s
```

새 브라우저 시험은 조사 성공 → 수집 접수 응답 유실 → 같은 요청 재확인 →
수집 완료 확인 → 검토 접수·보류 확인, 페이지 안의 화면 이동과 390px
가로 넘침 없음을 검사한다. API 단위 시험은 고정 부모 필드, 올바른 단계,
외부 필드/잘못된 ID 거부를 확인한다. 첫 전체 브라우저 실행은 기존 두
시험의 모호한 `대기 중` 텍스트 선택자로 **25 passed, 2 failed**였다.
작업 카드 안으로 선택 범위를 좁힌 뒤 해당 화면 **4 passed**, 이어서 전체
**27 passed**를 확인했다.

390px 실제 Chromium 화면을 확인하고 `12ui-design`의 기존 화면 개선
후보 두 장도 살폈다. 두 후보는 모바일 캡처를 데스크톱 화면으로 바꾸고
현재 단계·문구를 부정확하게 다시 그려 적용하지 않았다. 기존 디자인 안에서
세 작업 상태와 보류 근거를 구분하는 화면을 유지했다. 디자인 후보를
농업·제품 상태 근거로 사용하지 않았다.
