### 실제 늦은 전달2건

`cropResultPicker`의 농장 목록 조회는 하위 API에 취소 signal을 전달하지 않는다.
이 경로를 사용해 전송 취소와 별도로 generation/owner 경계를 확인했다.

1. 농장 목록 새로고침을 시작해 이전 생장/수확 표시를 비운다.
2. Chrome CDP의 Response 단계에서 **서버가 실제 반환한200 원 본문**을 보류한다.
3. 첫 경우는 사용자의 조회 취소, 둘째 경우는 다른 계정으로 연결 변경을 수행한다.
4. `Fetch.continueResponse`로 원 응답을 재개한다. 두 번 모두 성공했고 실제 Network200의
   전체 원 bytes/JSON/hash를 관측했다. 각각743bytes이며 최초 농장 목록과 동일했다.
5. 도착 뒤에도 이전 농장 선택 option/결과 행·생장 구획 수치/수확 수치가 없다.
   새 잘못된 계정의 별도 농장 조회는 실제401/error였고 이전 결과는 복원되지 않았다.

`Fetch.fulfillRequest`/본문 재작성은 사용하지 않았다. 실제 HTTP 요청12건은200×11/401×1이다.
보류한200 두 건은 이12건에 포함되며 추가 요청으로 합산하지 않는다. page/console error0이었다.
계정이나 브라우저 저장소에서 자격증명을 읽어 검증하지 않았다.

guard는 종료0/51.070356초, 단일362,582,016/합1,050,243,072bytes였다.
원512MiB/PID·합1GiB/600초/.25초 표본과 원 Chromium/pipe/viewport를 유지했다.
FD4→4·소유 프로세스/PG/passfile/임시 잔여0, 원5root/하위 서비스·원본2148개와
기존 두 frozen HTML/자산을 보존했다. 새 DB를 만들거나 기존 API를 재시작하지 않았다.
원 컴파일 소스/lock 핀과 빌드 자산은 그대로이며, 변경 가능한 개발 상태 JSON만
별도 현재 스냅샷으로 제공하고 전후 해시를 확인했다.
