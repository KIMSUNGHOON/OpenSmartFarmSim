## 전체 실행을 먼저 시작하지 않는 근거

현재 경로는 n번째 호출에서 다음 검사를 수행한다.

1. 재개 writer의 `_load_prefix`가 과거 n−1개 delta 전체를 검증한다.
2. 새 계산 delta1개를 검증한다.
3. 진행 조회의 `_load_prefix`가 현재 n개 delta 전체를 다시 검증한다.

따라서 delta 물리/수지 검증은 호출별2n회이며 실제32회에서도2,4,…,64회,
합 **1,056회**를 관측했다. prefix 읽기는63회/21.630초다.
이는 현재 source의 전체 순회와 일치하며 개별 호출의 단순한 고정 지연 문제가 아니다.
같은 경로가 원 순수 전체 실행의14,567개 commit 수를 따른다는 조건 아래
검사 횟수는 정수 산술 `N×(N+1)`로 **212,212,056회**다.
이 값은 source/호출 구조의 조건부 개수이며 전체 소요 시간이나 완료일의 예측이 아니다.

현재 경로로 장시간 전체 등록 계산을 시작하는 판단은 보류한다.
전체 작기 wall 예산은 다음 개선의 현재 bytes 검사·서명/물리 검증·재개와 실제 비용을 확인한 뒤 고정한다.
마감/중단 시 마지막 선택 signed HEAD만 보존하고 원 마감·입력/수식/한도를 유지하며,
같은 판본·현재 권리 아래 실제 checkpoint를 재개하는 절차와 실제 종료 기록이 필요하다.
최종 수용에는 등록181만여 걸음·47,809시점/5사건의 원량/수지·불변 게시,
DB/API/같은 UTC3D·소유 자원 정리의 해당 실제 증거를 각각 요구한다.

다음 [prefix 검증 증명 계약](../contracts/crop-cycle-calculation-prefix-attestation-v1.md)은
서버가 실제 검증한 새 delta를 명시 판본으로 서명하고, 재개/진행 조회는 전체 현재 bytes·서명 체인을
확인해 그 검증 증거를 소비하도록 한다. 새 delta와 최종 게시의 물리/수지 검증은 유지한다.
이 계약은 구현·수용 전이며 현재 검사를 metadata cache로 대체하지 않았다.
