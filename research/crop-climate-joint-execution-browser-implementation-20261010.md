## 실제 경로와 검증

- 모의 route 없는 제품 브라우저에서 검토된 합성 요청을 접수하고, 같은 job/farm의 대기→실행→서버 수용 체크포인트를 자동 조회했다. 동시 진행 GET 최대1개였다.
- 별도 `app.deterministic_work` 프로세스가 작업 ID 지정 없이 대기열을 소비했다. 실제 수치16걸음과 최초 양의 yielded 체크포인트15/16을 확인했다.
  시험 관측을 위해 그 확정 체크포인트 뒤 잠깐 정지했다. 계산값·시각을 만들어 넣거나 작물 애니메이션을 생성하지 않았다.
- 정상 완료는 원 저장3시점, 수치 hold는 원 저장2시점의 결과 ID/농장/UTC·상태 원값·50과실 구획·LAI/온도 WebGL 표현을 대사했다.
  화면의 농장 JSON은 필드 객체로 비교하며 키 직렬화 순서에 의존하지 않는다. 실제 canvas를 화면에 스크롤해 표시·draw call과 원 수치를 확인했다.
- 완료/hold 뒤 연결 해제→같은 job 재접속→동일 결과/체크포인트, 종결 작업의 취소 거부와 최종 상태 보존을 확인했다.
- 표시권 철회 후 실제 진행 조회422·기존 수치 삭제·서버 취소 수락·작업자의 취소 확인을 통과했다. 수치 계산0걸음·게시 결과0·임의3D0이었다.
- hold 경로의 첫 시도는16걸음 뒤 쓰기 충돌로 queued가 됐다. 같은 소비기의 다음 시도가 원 체크포인트를 채택해 hold를 게시했고 누적 계산은16걸음으로 유지됐다.
- 실제 HTTP reader의 원 응답 bytes와 브라우저가 소비한 bytes가 일치했다. 진행/저장 조회의21종 계산 계수는 모두0이었다.
  실제 인증·현재 권리·서명/DB 검사는 유지했다. 잘못된 CA 거부와 신뢰 CA의 HTML 일치, upstream 인증서 검증과 브라우저의 단일 인증서 SPKI pin을 사용했다.

브라우저 polling은 실제 타이머이며 `page.clock`을 사용하지 않았다. 인증 grant는 기존 native fixture의 제어된 clock을 사용하므로
실제 사용자 토큰의 만료/재발급 수용은 E9b에서 검증해야 한다. 이 입력은 짧은 합성 실행이며 전체166일 계산 속도·실제 농장 성능의 근거가 아니다.
