# 기존 제품 UI 동시 기동과 최종 통합 계획 — 2026-10-09

## 범위와 현재 결론

사용자 요청에 따라 기존 React `App`의 빌드와 실제 API/별도 PostgreSQL을 함께 기동했다.
`http://localhost:5173/`은 이번 실행에서 기존 제품 App을 제공한다. 기록 응답을 반환하는
`web/demo`/`OSSF_WEB_DEMO`는 사용하지 않았다. 기존 개별 화면은 있고 **최종 통합 UI는 미수용**이다.
보존된 작은 합성 부모의 원 3시점과 수확 제거·배정 원 5행을 실제 DB/API에서 읽는다.
실제 Axiany/Maxifort 생산 Run은 0건이고 생산·미래 마진·추천/G0–G4 상태는 바꾸지 않았다.

[불변 공개 관측](artifacts/product-ui-local-preview-reference-20261009.json)에 실제 HTTP,
브라우저 원 명령/종료·자원, native CLI model/effort, 실패한 앞선 브라우저 범위를 보존했다.
판단은 현재 native Codex CLI `gpt-6.1-sol` / `xhigh` 세션에서 수행했다. CLI 재귀 호출은 없다.

## 실제 실행 구성과 사용 방법

- 기존 앱: Node 22.22.3, `NODE_OPTIONS=--max-old-space-size=192 nice -n 19 npm run build`,
  원 도구 8342 종료 0. TypeScript 검사와 Vite 빌드를 통과했다. 기존 500 kB 초과 묶음 경고는 남아 있다.
- 프론트엔드: 기존 서명 확인된 로컬 Nginx 1.30.5와 `web/dist` 정적 빌드.
  브라우저 쪽은 loopback HTTP이고 API upstream은 인증서를 확인하는 HTTPS다.
  인증·응답·시각을 주입하거나 응답을 대체하지 않는다. 공개 배포 구성이 아니다.
- 백엔드: 기존 `ApiRuntime`/`HttpsApiService`의 공유 JobStore·농장·계산 결과·수확 조회 조립.
  새 내부 Bearer 읽기 권한만 발급하고 원 작물 입력/결과 서명 키·issuer/증명/최초 시각은 유지했다.
- DB: [수확 저장 보존 수용](crop-harvest-storage-preservation-small-implementation-20261009.md)의
  보호된 DB/역할 백업을 별도 포트의 소유 PostgreSQL로 복원했다. 삭제된 과거 임시 job artifact
  디렉터리 대신 빈 별도 소유 디렉터리를 API에 설정했다. 원본 자료나 작업 완료를 만들지 않았다.
  기존 정상 서명/현재 권리 검사를 거친 저장 결과만 반환한다.
- 원 도구 82604의 API/프론트엔드/복원 DB는 사용자 확인을 위해 **계속 실행 중**이다.
  09:12 KST에 시작한 원 전체 작기 계산(95086)의 프로세스·DB·입력과 분리했다.
  성공한 미리보기 프로세스의 종료/재기동 검증과 일반 사용자 동시 부하는 이번 수용에 포함하지 않는다.

접속 절차와 보호 파일 위치는 [웹 안내](../web/README.md#기존-제품-앱의-로컬-동시-기동--2026-10-09)를 따른다.
토큰은 저장소·공개 증거·명령 인자·화면 캡처에 포함하지 않았다.
현재는 내부 ID를 입력해야 한다. ID 수동 전달을 제거하는 저장 결과 목록은 U1의 미완료 작업이다.
경제 화면의 존재를 이 합성 작물 결과의 생산원가/마진 연결 완료로 해석하지 않는다.

## 확인한 검증과 보류

1. 실제 프론트엔드 `GET /` 200과 정식 빌드를 확인했다. 같은 origin의 실제 API 조회
   **생장 요약/시계열/사건, 수확 요약/원행 다섯 건 모두 200**, `Cache-Control: no-store`다.
   최대 20.567초·54,032 bytes로 기존 요청 30초 한도 안에서 완료했다.
   응답 bytes/SHA는 공개 관측에 기록했다. 전체 작기 또는 일반 부하의 응답 성능 증거가 아니다.
2. Playwright의 새 격리 Chromium으로 기존 App을 열고 실제 토큰/농장/결과로 조회했다.
   원 도구 **20806 종료 0·8.686초**. 페이지 오류 0, 생장 API 실제 읽기 2건,
   응답 대체/route mocking 0. 저장 첫·마지막 UTC의 실제 WebGL2와 draw call,
   LAI 면적·50개 과실 C/N 값·단위를 실제 서버 응답과 대사했다.
   3시점 중 두 끝 시점의 장면을 확인했으며 중간 시점 장면을 별도 검증했다고 주장하지 않는다.
3. 0.1초 간격 81회 관측의 최대 단일 RSS **401,113,088 bytes**, 소유 합
   **1,058,881,536 bytes**다. 이 합에는 원 전체 계산과 양쪽 DB도 포함했다.
   정해진 단일 512 MiB/합 1 GiB 아래였지만 일반 운영 용량 수용은 아니다.
4. 앞선 넓은 브라우저 검사(70128)는 생장 끝 시점 확인 뒤 수확 조회 중 합 RSS
   **1,089,314,816 bytes > 1 GiB**를 관측하여 소유 브라우저만 중단했다.
   원 종료 1과 이 보류를 보존했다. 이번 미리보기의 수확 **API** 조회는 통과했지만
   수확 **브라우저 전체 경로**는 자원 여유가 생길 때 확인한다. 앞선 별도
   [실제 수확 WebGL 수용](crop-harvest-view-native-implementation-20261009.md)의 다른 실행 증거와 구분한다.
5. 기동 초반 원 44336은 24시간에 1초를 더한 내부 grant 기간 거부로 종료 1,
   원 90877/99824는 삭제된 과거 job artifact 디렉터리로 조립 거부·종료 1이었다.
   기간을 기존 제한 안으로 수정하고 별도 소유 디렉터리를 설정한 새 실행 82604에서 기동했다.
   검사 중 SQL 권한·서명·schema/source guard를 완화하지 않았다. 실패한 복원 DB는 helper가 정지했다.
   그 세 정지 복원본의 data 디렉터리 125,896,598 bytes를 제거하고 원 백업·실패 기록을 보존했다.
   실행 중인 미리보기 DB와 전체 계산 DB는 이 정리에서 제외했다.
