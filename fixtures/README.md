# Self-authored synthetic fixture inputs v1

These two JSON inputs are small algebraic sentinels for a future G1 software-contract trace. They are self-authored, not provider observations, farm records, crop outputs, commercial prices, or measured greenhouse coefficients. The manifest's `synthetic_input_review_id` is an author-declared review reference for later server verification. It is not an external-source G0 approval or an accepted thermal Run. The current generic G0 evaluator holds synthetic records. The deterministic thermal and economic engines, their numerical rules, and actual G1 result checks are later tasks.

The weather file has adjacent UTC `[start_utc,end_utc)` intervals. `T_o` is kelvin, `phi_o` is a dimensionless fraction, and `p_o` is pascal. `solar_interval_energy` is the **total J/m² over that interval**; the zero is explicit. There is no gap fill. In `Asia/Seoul` on 2026-10-15, the first interval converts from 08:00–09:00 UTC to **17:00–18:00 KST** and has positive interval energy; the second converts from 09:00–10:00 UTC to **18:00–19:00 KST** and has explicit zero energy. Both are algebraic sentinels. Neither value claims astronomical consistency or local weather. A later engine must derive `w_o` with a registered saturation-pressure law, divide interval energy by duration for incident W/m², then use separately sourced area and absorbed fraction for aggregate solar W. This fixture supplies neither result nor a passing trace. The thermal input and trace requirements are in [thermal-v1](../contracts/thermal-v1.md).

This fixture package defines **INPUT only**. The final thermal trace requires `source_records[*]` and `synthetic_input_review_id`; this fixture does not supply a completed source-record array or an accepted trace. A future deterministic adapter and server must derive records for each interval and variable, bind each record to the manifest's raw SHA-256 and local `source_locator`/`product_id`, preserve the exact original units and interval time semantics, and name the versioned normalization rule. They must check the author and synthetic label, provider QC (`not_applicable` for self-authored inputs where appropriate), project QC, reviewer, and self-owned use/display/redistribution rights. The server must independently verify the synthetic input review and every record link before accepting a G1 software-contract trace. The manifest's self-review declaration alone establishes neither an actual G0 pass nor field accuracy.

The economics file uses exact decimal strings for all quantity and money inputs. Every numeric economic input carries `origin=user`, `evidence_level=assumed`, and `assumption_scope=self-authored algebraic sentinel v1`. The hypothetical `decision_at_utc` precedes all conditional events. Harvest `H`, packout `P`, recognized sale `S`, cull/disposal, and opening/closing saleable inventory conserve mass. Dispatch, delivery, inspection, and recognition occur on one Asia/Seoul day; later collection and cost payments have distinct dates. Only recognized `S` earns conditional revenue. Production input cost covers all harvested units once, including unsold inventory. The demand, supply, and macro drivers form one jointly applied user assumption with explicit sale cap, farm contract price, input cost, quantity, inventory, collection, and timing consequences. There is no automatic passthrough or probability. See [ECONOMICS](../docs/ECONOMICS.md) and [MARKET_INTELLIGENCE](../docs/MARKET_INTELLIGENCE.md).

`MarketContext` is exactly `{ "kind": "unavailable", "hold_report_id": "market-hold-synthetic-v1" }` in the economics file and manifest. The manifest's hold report names the missing evidence. There is no MarketSnapshot, market source G0 pass, crop yield or price forecast, purchased energy, future margin, ranking, or G2/G3 result. Assessment intent is `hold`.

## Byte pins and IDs

- The canonical content ID for each input is `sha256:` followed by the lowercase SHA-256 of its **complete raw UTF-8 file bytes**, including indentation and final newline. `byte_length` counts the same bytes. The manifest binds repo-relative paths to those IDs, not to parsed or reserialized JSON. JSON values never contain their own raw hash.
- `fixture_id` and `manifest_id` are semantic version labels. `vintage_id` and `revision_id` identify this authored release. A changed byte requires a new fixture revision and manifest; do not silently replace a pinned release. The manifest cannot contain its own raw hash without a cycle. A consumer may compute its content ID as `sha256:<SHA-256 of complete raw manifest bytes>` and pin that in an external immutable run record.
- `source_locator` is the local fixture path and `product_id` is the fixture ID. Neither is a third-party source URL. Manifest authoring/publication/availability/retrieval times are before the economics `decision_at_utc`. The later weather interval is hypothetical, not an observed decision-time source; economic event dates are conditional assumptions. Rights for the self-authored files are access, store, transform, display, and redistribute under the repository's [Apache-2.0 license](../LICENSE). The self-check and reviewer fields are author declarations for software tests, not server gate evidence.

```sh
wc -c fixtures/synthetic-weather-v1.json fixtures/synthetic-economics-v1.json fixtures/manifest-v1.json
```
