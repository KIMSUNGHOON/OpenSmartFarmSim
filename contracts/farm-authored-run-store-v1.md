# Authored thermal Run storage boundary v1

Status: internal storage and transaction boundary after [Run byte preparation](farm-authored-run-preparation-v1.md). A synthetic software test inserted and reread a row. No product-authorized authored Run has been published.

The owner installs `authored_thermal_runs` after the durable job and authored release tables. A row has a tenant/Run primary key, one simulation job, one completed review release, the registration and scenario revision, exact two final trace byte strings and SHA-256s, preparation and publication report bytes and SHA-256s, and a server HMAC gate signature. It has tenant/job foreign keys, byte-digest and critical identity/carry checks, and an owner-installed trigger that rejects update and delete. A deferred constraint trigger requires the same transaction to leave the simulation job succeeded with an exact `job_publications` manifest binding its Run ID, attempt, input digest and artifact digest. A Run insert alone cannot commit.

The internal store method accepts only a live, uncanceled simulation lease whose canonical `authored-thermal-simulation-input-v1` bytes bind tenant, review job, authored scenario ID/revision and registration digest. It calls the installed `AuthoredRunPreparer` again, requires exact packet bytes, signs a separate canonical accepted publication report and inserts both traces in that existing transaction. The caller must create the exact receipt, terminal event/outcome and job publication before commit. An identical Run retry is byte-checked; a conflicting row holds. A read requires tenant scope, the succeeded job and publication, receipt bytes, original trace/report hashes, gate signature and a freshly revalidated current release/input. Revoked rights or changed trusted code hold the read without rewriting history. These guards are software contracts; G1 still requires an actual independently reviewed release and product CLI execution.

`RuntimeLoginPolicy(authored_run_storage=True)` is an explicit profile that requires `authored_release_storage=True`. The authority login alone receives `SELECT, INSERT`; request, worker and supervisor logins receive neither. Its audit version is `runtime-authored-run-login-policy-v8`. Existing profiles do not acquire the table. The [focused PostgreSQL/SCRAM test](../research/farm-authored-run-store-implementation.md) checks role grants and synthetic store behavior. The actual worker and API/3D projection, product CLI, independent release and G1 evidence remain pending.
