# Supply-limited successor Context and seed checkpoint, research v1

This additive owner adopts the actual [successor material point](crop-supply-morphology-newborn-point-v1.md) on its genuine first post-material source owner and evolved checkpoint. It does not manufacture an older typed handle. It is a seed-only family: time integration, repeated events, result publication and the user UI are subsequent tasks.

`crop_supply_morphology_successor_context.prepare_context(origin, raw_checkpoint, expected_sha256=..., time_tolerance_seconds_exact=..., inputs=...)` executes the actual accepted candidate and material operation, captures their original bytes and rechecks caller inputs and tolerance through return. The owner binds the source Context, point hash and current source-code closure.

The immutable seed preserves the after-program, state, ordered organ IDs, construction costs, state layout, carbon/thermal birth bases, **explicit per-organ geometry origins**, unified physical/geometry lifetime channels, point totals and global accounts. Prior newborn organs retain their original seed dimensions and inflow origins; their grown current dimensions never replace those origins. New dimensions and initialization remain exactly the declared compatible seeds. No coefficient or budget is repaired.

Consume exactly the actual source event, then increment its sequence once and add the original source phyllochron. Retain the computed numerical air-integral age without snapping. Preserve original step, count, horizon, floor grid index and exact fraction remaining to the next original endpoint. Append dense-before and actual-after samples, each binding its sample hash, phase, sequence, point hash and model version; cursor increases by two. This immutable stateless capture is not a persistent farm event-log lock.

`context_bytes`, `point_bytes`, `start`, `checkpoint_bytes` and `restore_context(origin, raw_bytes, expected_sha256=..., point_bytes=...)` validate genuine ownership, bounded canonical bytes and trusted hashes, direct saved receipt arithmetic, current source/profile/code/rights and the complete point-derived seed. They perform zero coupled RHS evaluations, candidate/material operations, funding calls, leaf initializations or time advances. Pure receipt equations and source/hash reads are permitted.

The seed checkpoint has zero branch transfers/residuals/budgets, unchanged exact lifetime/point/global accounts, current after-point sample, consumed schedule and prefix. It is not an evolved checkpoint. `restore_checkpoint(context, raw_bytes, expected_sha256=...)` first requires the complete canonical seed payload, evaluates the actual current birth stage once, compares its full saved output and rechecks input/profile/source/code fences. Unexpected RuntimeError propagates; known failures raise SupplyContextHold. Rehashed descriptor/CP changes, including equal-valued JSON type changes, cannot replace the exact seed.

Descriptor plus point bytes remain bounded by2MiB, CP512KiB, organs512 and original32768-scalar/horizon limits. No DB, worker, network, new renderer or external data is introduced. Synthetic software evidence leaves G0–G4 not_assessed and R2 not_approved. The next family-specific task implements explicit-origin accounts and original-grid/evolved checkpoint continuation; only after that can repeated adoption and immutable same-state3D be accepted.
