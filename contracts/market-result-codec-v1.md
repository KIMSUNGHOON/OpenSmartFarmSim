# Conditional market result JSON codec v1

Status: synthetic software serialization candidate. The market and economic calculation engines remain conditional G1 software; this codec does not publish a Run, forecast, net farm price, margin validation, or crop ranking.

`encode_market_result` emits canonical UTF-8 JSON with exact top-level keys `codec_version="market-result-v1"` and `result`. The result contains the complete `MarketScenarioResult` and nested `EconomicResult` fields. Every field except `economic_result.closing_inventory` uses Pydantic's JSON representation. That inventory has tuple keys `(batch_id, grade, channel)` in Python; a generic JSON object would join the elements with commas and could merge distinct keys when identifiers themselves contain commas. The codec instead writes `null` for unknown inventory or a sorted list of `{batch_id, grade, channel, quantity_kg}` entries, with finite nonnegative decimal strings. Empty inventory remains an empty list. Decoding rejects duplicate lanes, invalid values, unknown result fields, duplicate JSON keys, noncanonical bytes, and payloads over 1 MiB, then reconstructs the exact tuple-key dictionary and verifies that re-encoding yields identical bytes.

The [focused tests](../backend/tests/test_market_result_codec.py) round-trip a calculated market/economic result, unknown inventory, two colliding comma-delimited lane names, reversed insertion order, and malformed payloads.

`MarketResultStore` stores the server-calculated bytes in an immutable, tenant-scoped PostgreSQL row keyed by the candidate scenario and revision. The row binds the result ID, candidate ID, and economic scenario SHA-256; the database checks its raw SHA-256 and candidate foreign key. It requires `market_result_write` to pin and `market_result_read` to retrieve, in addition to the candidate source's read authority. A retry must match the first stored bytes. Retrieval decodes and checks the row, then recalculates the candidate, rights, signed Market hold, joint shock, settlement and economic ledger path through `MarketScenarioService`; it rejects any changed result bytes. The [signed-hold integration test](../backend/tests/test_market_signed_hold_integration.py) exercises a new store instance, retry, immutable row, scope denial, and changed hold scope against PostgreSQL 16.

This is a conditional software result. The baseline, shock, rights, settlement, and plan-event sources in the integration test remain in memory. There is no retrieval API, independent source authority, production database role proof, or product display permission yet. The assessment remains `hold`; this does not establish a verified farm net price, future margin, crop ranking, or G1 release.
