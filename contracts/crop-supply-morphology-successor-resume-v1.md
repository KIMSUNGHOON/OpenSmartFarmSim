# Successor-family original-grid continuation, research v1

This additive integrator requires the genuine [successor Context](crop-supply-morphology-successor-context-v1.md). It creates its own evolved checkpoint type; neither the seed-only owner checkpoint nor a genuine older-family checkpoint is a continuation handle. Old accepted validators remain unchanged.

`crop_supply_morphology_successor_resume.start(context)` uses the exact saved fractional after-material state and unified lifetime/point/global accounts. It performs no RHS evaluation, material operation, funding or initialization. `checkpoint_bytes` validates and exports its bounded canonical payload without RHS work. `restore_checkpoint(context, raw_bytes, expected_sha256=...)` requires trusted original bytes/hash, exact complete canonical shape, current sources/profile/code/rights and one actual current birth-stage evaluation. It never reintegrates a past interval or replays a material event.

`advance_chunk(context, checkpoint, step_budget)` accepts an integer1..128 original endpoints. It integrates the exact fractional remainder to the next original grid time, then the original step; the original horizon/count stay fixed. Each interval uses actual shared birth-stage RK4 stages and an endpoint evaluation, with1current validation and4new RHS per attempted interval. All ordered physical/geometry states and flux channels stay in the same actual inventory.

Branch accounts start at the after-material seed. Lifetime physical/geometry transfers retain their explicit original origins. Global geometry/partition/construction equations use each saved geometry_baseline ID, original dimension and original physical inflow, including earlier newborn organs; their currently grown dimensions never replace the original seed dimensions. Carbon/thermal birth baselines, construction costs, point totals and exact global residual/budget composition remain authoritative. Potential, realized, deficit and canonical-gap diagnostics describe synthetic model behavior, not observed growth.

A confirmed endpoint binds the prior prefix, full sample, branch step, actual Context and seed-owner CP hash. Full, split and cold-resumed executions must yield identical endpoint samples and final CP bytes. Schedule/event sequence remains unconsumed. If the next threshold lies in an interval, return an unrefined monotone bracket and the last confirmed prefix; issue no candidate, organ or checkpoint object for that interval. Refined next-event/material adoption is a later family-specific task.

Supported numerical/domain failures retain only the confirmed prefix. Current or late source/profile/code/caller/stage-input changes discard unpublishable samples/prefix. RuntimeError propagates. Original2MiB result/context limits,512KiB CP, inventory512 and32768-scalar/horizon limits remain. No network, database, worker or UI is added; G0–G4 stay not_assessed, R2 not_approved. Full-cycle performance, real cultivar calibration and independent field validation remain unaccepted.
