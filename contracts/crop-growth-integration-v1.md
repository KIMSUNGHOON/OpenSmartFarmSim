# 작물 상태 시간 적분 v1

상태: **로컬 소프트웨어 수용, 2026-10-04**.
[실제 146개 시험/참조 적분](../research/crop-growth-integration-implementation.md)을 확인했다.
기존 CLI `gpt-6.1-sol / xhigh` 세션에서
설계한다. 선행은 [유량 계산](crop-growth-research-v1.md)과
[작은 수관 적용 정책](crop-photosynthesis-domain-v1.md)이다.

## 계산과 입력

순수 함수 `integrate_crop(initial_state, segments, events, output_times, profile, solver)`는
기관/버퍼 CH₂O·평활 온도·온도 합의 ODE를 적분한다. 광 동화·생장 호흡·기관별
유지 호흡·기관별 제거도 같은 수치 가중치로 누적한다. 생과 kg·숙기/키/개수·물/구매
에너지·금액을 만들지 않는다. 출력 scope는 `software_research_only`다.

- `initial_state`: 유량 모듈의 닫힌 상태 블록. 첫 시각의 제거 사건 전 상태다.
- `segments`: 연속/중첩 없는 순서 있는 `{start, end, forcing, removals}` 목록.
  forcing/PAR/CO₂와 명시적 연속 제거 유량은 해당 구간에서 일정하다. 구간은
  `[start, end)`이며 마지막 끝 상태를 계산하기 위해 마지막 입력의 좌극한을 사용한다.
- `events`: 순서 있고 시각이 겹치지 않는 `{at, removals}` 목록. removals는 명시적
  잎·줄기/뿌리·과실 CH₂O 제거 질량 블록이다. 모든 기관의 값/단위/출처를 명시한다.
  사건은 순간 제거량이며 관리/수확 시점을 모델이 자동 생성하지 않는다.
- `output_times`: 전체 시작/끝을 포함하는 증가하는 출력 시각. 입력 UTC는
  `YYYY-MM-DDTHH:MM:SSZ`의 정수 초이며 POSIX UTC 시간 차를 사용한다.
- `profile`: 이미 바이트가 고정된 참조 프로필. 실제 품종/G0 승인 아님.
- `solver`: 정확히 `{method: "rk4-fixed-v1", max_step_seconds, max_steps,
  roundoff_rule: "64-ulp-per-operation-v1"}`. 두 한도는 명시적 정수다.

각 목록은 최대 20,000개, max_step_seconds는 1~86,400초,
max_steps는 1~1,000,000이다. 이는 연구 작업의 연산/메모리 한도이며 재배 범위가
아니다. 입력·필요 단계 수·한도 위반은 `CropIntegrationHold`로 계산 전에 거부한다.
초기 상태/환경/제거 블록은 유량 모듈의 동일한 단위/출처 검사를 재사용한다.
생리 범위는 실제 적분 상태와 해당 시각의 forcing에서 평가한다.

## 솔버·사건 순서와 실패

명시적 4단계 RK4로 `h*(k1+2*k2+2*k3+k4)/6`을 적용한다. 구간 변경·제거 사건·
출력 시각마다 단계를 끊는다. 마지막 남은 간격은 max_step_seconds보다 작을 수 있다.
단방향 forcing의 온도 합은 시간에 대한 독립 선형식이므로 `Tcan*구간 초/86400`의
정확한 Fraction 합으로 각 단계/출력에서 평가한다. 큰 초기값에 작은 증가량을 반복
차감/더하는 반올림 손실을 피하고 동일한 DE의 정확한 해를 사용한다. 이 방법 판본을
manifest에 보존하며 새로운 작물 계수나 생리 식을 추가하지 않는다.
RK4는 조건부 안정성과 유한한 절단 오차가 있으므로 작은 h 자체를 정확성 증거로
사용하지 않는다. [MIT 원 수치 방법 설명](https://ocw.mit.edu/courses/es-1803-differential-equations-spring-2024/mites_1803_s24_topic11.pdf)의
표준 가중치/수렴 원리를 참고하며 코드는 직접 작성한다. 새 라이브러리를 설치하지 않는다.

경계 순서는 **이전 forcing으로 경계까지 적분 → 명시적 제거 적용 → 새 forcing에서
상태 검증 → 출력**이다. 같은 UTC의 출력 상태는 사건 후 상태이고 사건 원장에
별도의 이전/이후 상태·제거량을 기록한다. 시작/마지막 시각의 사건도 한 번만 적용한다.
제거량이 재고보다 크면 중단하며 state를 0으로 clip하지 않는다.

각 RK 단계와 최종 상태에서 유량 모델의 수관/평활 온도·LAI/CO₂·고갈 영역을
검사한다. 음의/비유한 상태·누적량·수지 실패도 중단한다. 유효 프로그램에서
발생한 수치/모델 실패는 `status=hold`, `samples=[]`, `events=[]`로 반환한다.
hold에는 원 reason, `attempted_at`, `phase`, 마지막 확인 상태/시각·누적량,
실패한 상태와 모델/프로필/입력 해시를 기록한다. 비유한 실패 값은 진단의 null로
표현하고 원인을 기록한다. 실패 시각은 **솔버 평가 시각**이며 실제 생리적 고갈
시각으로 게시하지 않는다. 실패 뒤 부분 결과를 완료 시계열로 내보내지 않는다.

## 수지·버전과 수용

CH₂O 총 저장 변화는 누적 광 동화 − 생장 호흡 − 유지 호흡 − 연속/사건 제거다.
분배는 내부 이동이며 다시 외부 소비로 차감하지 않는다. 사건 제거는 상태와
누적 제거량에 한 번씩 대응한다. 모든 확인 상태에서 탄소 잔차를 검사한다.

수지의 이진64 반올림 예산은 `64*(accepted_steps+accepted_events+1)*ulp(scale)`다.
scale은 1 또는 초기/현재 총 탄소·각 누적량 중 가장 큰 절대량이다. 단계/누적
덧셈·소거와 양쪽 수지 평가의 오차 여유를 둔 **수치 검사 예산**이며 생리 허용 오차가
아니다. 절단 오차/실제 정확도 검증을 대신하지 않는다. 참조 허용 기준은 구현 전에
등록한다: CH₂O 상태/누적량 absolute `5e-9 mg_CH2O/m2_floor`, LAI `5e-13`,
평활 온도 `5e-12 degC`, 온도 합 `5e-15 degC_day`.
고정밀 기대값은 먼저 가장 가까운 이진64 수로 변환해 비교한다. 이 비교 오차는
출력 표현 자체의 반 ULP 오차와 별개이며 실제 Decimal 차이도 결과 보고서에 기록한다.

manifest는 integrator/rate model·정책 ID, profile/코드/정규화 입력 해시,
솔버/시간 규칙·Python 판본·입력 origin 목록을 보존한다. 동일 환경/입력 재실행은
같은 결과 해시를 만든다. 교차 환경 비교는 버전을 기록하고 등록 수치 예산으로
별도 대조한다. reference origin/입력 ID는 권리 승인이나 G0 증거가 아니다.

수용 기준:

1. 제품 함수를 import하지 않은 고정밀 문헌 RHS/참조 적분과 시계열을 비교한다.
2. 평활 온도와 온도 합의 독립 해석해·탄소 수지·관리 사건 전후/순서·중복 제거를 확인한다.
3. 같은 프로그램의 h·h/2·h/4 결과가 고정 참조로 수렴하는 사례와 범위/음수/고갈/
   과다 제거/예산 초과의 명시적 실패를 확인한다. 모든 작기의 수렴을 일반화하지 않는다.
4. 입력 비변경·출처/솔버/시각/사건 변경의 해시 연결과 동일 환경 재실행을 확인한다.
5. 실제 명령/결과·CLI 모델/effort·입력/코드 해시·보류를 기록한다. 샘플 파일은
   소프트웨어 연구 산출물이며 아직 불변 DB 결과·G1 Run·성장 3D가 아니다.

한 번 완료된 적분 결과에는 `convergence=not_evaluated_for_this_program`을 표시한다.
해당 manifest의 독립 재계산/수렴 증거와 별도 입력 G0·해제 없이 제품 Run을 게시하지 않는다.
실제 Axiany 작기 재현은 입력 감사 뒤, 국내 미래 생산/추천은 기존 G2/G3a/G3b 뒤다.
