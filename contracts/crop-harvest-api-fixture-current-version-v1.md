## 현재 값과 과거 증거

원8784의 기존74실패는 공개 영수증의 과거 artifact code와 현재 code의 불일치다.
과거 영수증·서명·record/UTC·행·해시를 변경하지 않는다. 현재 `_pins`나 판본 검사를 완화하지 않는다.
기존 실제 DB 값 검증을 소유 codec/가짜 DB 값의 검사로 축소하지 않는다.

현재 코드와 잠금에서 기존 정상 작은 계산/원 게시·증명→수확 `put`→실제 SCRAM reader를
임시 소유 DB에 실행한다. 기존 current-query native 시험의 현재 권리/scope/tenant·변조 거부,
별도 Python2개의 같은 DB 읽기·조회 RHS/행 생성/게시/proof0·FD·DB/PG 정리까지 확인한다.
원 실제 종료0와 별도 root 감사 뒤에 원 record/6행/summary/identity만 별도 공개 영수증으로 채택한다.
원 명령/코드 해시와 소유 합성 범위를 기록하고 DSN/비밀 key/개인 자료·임시 설정은 공개하지 않는다.
이 새 영수증의 해시를 고정한 현재 fixture를 기존 두 API 시험이 읽는다.

과거 fixture는 별도 이름으로 유지하고 현재 metadata decode/공개 projection 거부와
조회에서 성공 응답을 내지 않는 경계를 확인한다. 현재·과거 source를 섞거나 과거 payload를 다시 서명하지 않는다.

## 수용

1. 현재 실제 DB/서명/query·6행/summary와 fresh 별도 Python 증거가 원 종료/정리를 통과한다.
2. 기존 projection·보호 ASGI의 정상/권리/취소/범위/변조 검사가 현재 영수증으로 통과한다.
   별도 과거 판본 거부와 원 영수증 SHA/bytes 보존도 통과한다.
3. 기존30초/2MiB·현재 전후 권한 검사·제품 코드/DB 스키마는 유지한다.
