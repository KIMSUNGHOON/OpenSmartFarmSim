# Repeated funded organ events, research v1

Introduce a genuine successor Context/Checkpoint family. `adopt_first(origin_capture, raw_original_continuation_cp, expected_sha256, time_tolerance_seconds_exact, inputs)` evaluates the accepted first successor material API and issues a new context. `adopt_successor(context, raw_own_cp, ...)` evaluates the next event using that new family. Never fabricate an older typed context/checkpoint or reset initial source biology. Keep the original capture as a genuine immutable authority; original modules and pins remain unchanged.

Each new context records the original capture hash, versioned source pins, bounded ordered material-receipt hashes and the latest captured seed. Full immutable receipts are separately required for restoration and are authenticated against those hashes. Context/checkpoint/each receipt retain 2-MiB/512-KiB/2-MiB bounds; additionally bound the entire receipt collection to 16 MiB and 512 events. This limits proof memory without nesting copies of past contexts or candidates inside each receipt. Expected hashes must come from trusted storage; caller self-hashing is not farm custody. No new server/storage dependency is introduced by this pure in-memory interface.

Preserve the original stock source-context/checkpoint pair and separately bind each latest material parent-context/checkpoint pair. Reference parameter objects must still equal their original raw-profile construction, including all values and domain metadata, on each current-authority check.

Adoption validates the complete current candidate/point receipt and all identifiers, source/CP/input hashes, original profile costs, exact event time, existing state preservation, point balances and rights. Compose global books directly from the original root and actual birth baselines: each after-point residual is the before-global residual plus its corresponding point residual; the budget is exactly their existing sum. New age/carbon channels start from their actual zero continuous-transfer basis. Preserve old carbon/age/area/D0 and all old birth/air bases. Consume the current logical schedule once without conflating its threshold sequence with material-event count.

Start and immutable context validation/restoration use algebra and retained receipts, with no prior RHS, material jumps or initialization. Current checkpoint restoration evaluates exactly one current RHS. Same-time source/point verification is algebraic, not a re-execution of past material operations. Use original shared-stage rational-time RK4 to advance the exact remainder to the next original grid, then complete intervals. Stop at the first actual next-event bracket; the new-family candidate/material methods can consume that bracket and issue the next context. Do not skip multiple due events or snap clocks.

Perform full algebra verification on construction and every new restored handle. Reuse that verification only for the same immutable Context object, original-capture bytes/hash, complete immutable receipt hashes and current code pins. Recheck canonical context bytes, receipt types/count/size/hashes, source/profile/rights and code fences on every use. Any changed stamp requires full validation; neither source authority nor current checkpoint/RHS validation is cached. Weak object ownership must not retain past context objects indefinitely.

Preserve current samples/IDs/point and continuous transfers, exact current+local/global ledger identity and original budget sums, scope, rights, cursor/prefix and immutable source hashes. Chunk boundaries do not subdivide intervals. Whole/split runs and restores produce identical final bytes. Failed unconfirmed stages return only the confirmed prefix; current/late source/profile/code/rights/input/context changes prevent publication, and RuntimeError propagates. Preserve original horizon/step, inventories, remaining-scalar and resource limits. No geometry, farm deployment, crop production/economic prediction, recommendation or G0–G4/R2 approval.

Acceptance requires actual first successor adoption, repeated later events to the explicit original horizon, genuine new-family candidate/material execution, precise remainder and complete old/new inventory/birth clocks/global books, whole/split/restore identical bytes, zero past replay/initialization, raw/proof/trust/hash/semantic/duplicate/no-skip/late/domain/cap failures, independent arithmetic and separate producer/consumer, and old data/UI/WSL preservation. Keep the task and parent incomplete until these complete-path checks pass. Then implement supply-limited morphology and immutable same-state realistic 3D.
