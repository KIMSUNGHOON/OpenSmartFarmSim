# Authored farm Run preparation v1

Status: internal byte-preparation candidate after an [immutable signed release packet](farm-authored-release-store-v1.md). No authored Run is published or available to the 3D viewer by this contract.

`AuthoredRunPreparer` accepts the exact installed farm authoring service and release store sharing one job authority. Given tenant, completed review job, authored scenario ID/revision and registration SHA-256, it reads the stored release through its current signature, report, rights, completion and runtime-code checks. It independently recalculates the registered 120-step thermal candidate from the currently owned input. A changed source right, registration, numerical input, code or signed request returns a generic hold. It compares the current code and lock manifest again before returning.

`build_authored_run_packet` derives a versioned Run ID from the tenant, registration, completed review input/job, exact candidate ID and two candidate trace SHA-256s, decision context/time and signed release/request digests. It constructs two canonical bounded trace byte strings. The 60 calculated steps in each trace are copied unchanged; the second trace's initial-state references are rebound to the **final first-trace ID and SHA-256**, with the final state values and units checked. Each final trace binds its candidate trace, scenario revision, review decision/capture, signed context, release and calculation versions. The canonical report carries the final two SHA-256s and `status=prepared_unpublished`. The trace bytes are shaped for a future accepted publication, but their `status=accepted` field is not a gate verdict until a transactional publisher stores and verifies them. The preparer neither writes a Run nor changes a job state.

The only claim scope is `synthetic_thermal_replay_only` for the model's temperature, humidity ratio and heat quantities. No purchased electricity/fuel, crop growth, yield, future margin or crop ranking follows from these bytes. A [synthetic software worker](farm-authored-simulation-worker-v1.md) now tests atomic Run/job publication. An actual product CLI run, independent reviewer issuance, versioned authored snapshot acceptance and a separate authored API/3D projection remain required for G1. The original fixed-fixture Run and viewer contracts are not silently reused.

[Focused software evidence](../research/farm-authored-run-preparation-implementation.md) uses a synthetic signing key and a fake CLI. It does not validate farm physics against field measurements or accept G1.
