# 저장된 조사·수집·검토 작업 이력 v1

상태: 내부 소프트웨어 후보, 2026-09-30. [제품 명세](../docs/PROJECT_SPEC.md)의 첫 합성 경로와 [아키텍처](../docs/ARCHITECTURE.md)의 테넌트·불변 작업 계약을 따른다. 이 조회는 현재 G0/G1 승인이나 자료 채택을 만들지 않는다.

## HTTP 계약

- `GET /v1/source-history?limit=20&before_created_at=...&before_job_id=...`는 소유 테넌트의 조사 작업을 `(created_at, job_id)` 역순으로 훑는다. `limit`은 1–50이며 두 커서 값은 함께 제공한다. 응답은 `items`, `next_cursor`다. 다른 조사 계약의 작업은 목록에서 제외한다. 페이지 경계는 저장된 전체 조사 작업 기준이므로 해당 페이지에 표시할 소유 원본 조사가 없더라도 다음 커서가 있을 수 있다.
- 각 `items` 원소는 공개 작업 상태, 좌표, UTC 기간, 목표 ID, `current_authority=available|hold`만 포함한다. 현재 원본·등록 범위·서명 문맥을 다시 확인할 수 없으면 `hold`로 표시한다. 기록의 존재와 현재 사용 가능성은 별개다.
- `GET /v1/source-history/{research_job_id}`는 동일 테넌트의 정확한 조사 작업과 연결된 **가장 최근** 소유 원본 수집 및 그 수집의 가장 최근 검토 작업을 반환한다. 응답은 `research`, `collection|null`, `review|null`이다. 다른 조사·수집·테넌트의 작업, 입력 해시가 다른 연결은 허용하지 않는다. 과거의 모든 수집·검토 시도를 나열하는 API는 아니다.
- 두 경로는 Bearer 인증과 `metadata`, `decision_context_read` 범위를 요구한다. 원본 바이트, CLI 기록, 서명 문맥 ID, 자료 이용권 원문은 응답에 없다. 존재하지 않거나 다른 테넌트인 정확한 조회는 404이며 연결 훼손은 422 보류다.

웹은 연결 토큰을 다시 받은 후 목록을 요청한다. 항목을 선택하면 단건 조회로 현재 권한과 저장된 부모 연결을 다시 확인하고 조사·수집·검토 상태를 표시한다. `current_authority=hold`인 항목은 과거 기록으로만 열며 새 수집·검토 접수를 막는다. 작업 상태 갱신과 새 접수는 기존 API가 다시 현재 권한·자료·해시를 검사한다. 검토 보류 보고서는 별도의 기존 조회를 사용한다.

합성 자료 작업 완료는 실제 원천 G0, 작물·경제 예측, G1 Run 또는 공개 G4 운영의 증거가 아니다. 이 경로의 [시험 기록](../research/owned-source-history-implementation.md)은 저장 이력 복구 소프트웨어 범위만 다룬다.
