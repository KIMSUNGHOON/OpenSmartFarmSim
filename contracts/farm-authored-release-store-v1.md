# Authored farm release packet storage v1

Status: internal immutable custody candidate after the [signed release verifier](farm-authored-release-v1.md). This stores a reviewer packet; it does not issue a reviewer signature, approve a new authored snapshot or publish an accepted Run.

An authority caller with `authored_release_write` submits the tenant, completed `collection_review` job ID, registration SHA-256, release/signature/evidence bytes and the three report bytes. The exact release verifier first rechecks the completed job, current source rights and code, separate reviewer signature, reports and their referenced evidence. The store then requires the same tenant's succeeded review job and input digest. Its PostgreSQL row has a tenant/job foreign key and stores each bounded original byte string and SHA-256, reviewer, issuance time and recording time. Database checks bind request/release/evidence/report digests and critical JSON identities and versions. An owner-installed trigger rejects UPDATE and DELETE; identical retries return the original packet, while changed bytes for that review job conflict.

A caller with `authored_release_read` can retrieve the packet only for the same tenant and expected registration. Reads recompute all current verifier checks and compare the stored raw bytes and digests, including issuance before recording. Revoked rights, missing evidence references, modified code/lock, changed trust keys or a corrupted row hold without rewriting historical evidence. The packet remains an input to a future publisher; a stored row alone never clears G1.

`RuntimeLoginPolicy(authored_release_storage=True)` is an explicit fresh profile variant. It adds the table to the exact grant audit and gives only the authority login `SELECT, INSERT`; request, worker and supervisor logins receive neither. The policy reports `runtime-authored-release-login-policy-v7`. Existing login profiles do not gain this table automatically. The owner must install the additive schema before provisioning those fresh roles. No deployed role, reviewer signer, production credential or operating custody is created here.

The [SCRAM software test](../research/farm-authored-release-store-implementation.md) uses a real completed job from a fake CLI worker, a constructed completion proof and a synthetic reviewer key. It proves storage and role behavior, not a genuinely independent source/numerical review or actual product model invocation.
