# 저장 목록 재생의 소유 API 수명 검증 v1

U1의 남은 재시작/현재 권리 검증을 위한 내부 합성 시험이다.
선행은 [현재 제품 빌드의 저장 reader 재생](../research/catalog-stored-replay-current-browser-20261020.md)이다.
새 제품 API·역할·작업 큐나 구판 CODE 허용 규칙을 추가하지 않는다.

## 첫 단계: API 수명과 권리

- 지원하는 원 reader 판본으로만 소유 API를 조립한다. 원 결과/manifest/서명과 입력 경로를 유지한다.
- 원 합성 dump를 독립 소유 PG에 복원하고 SCRAM·다른 PG identity를 확인한다.
  원 트랜잭션/행 잠금 검사를 유지하며 계산/증명 발행/결과 게시를 차단하고 전후 counts/원 결과를 대사한다.
  보호 DB 공유 후보는 실제 read-only 확인 뒤 조회가25006으로 거부돼 채택하지 않았다.
  잠금/검사를 생략하거나 보호 DB를 읽기·쓰기 연결로 시험하지 않는다.
- 현재 권리와 principal의 동적 제어 파일만 소유 디렉터리에 복사한다. 원 파일을 바꾸지 않는다.
  기존 권리 검사 구현을 그대로 사용하며 새 입력 권리를 승인하는 우회 경로를 만들지 않는다.
- 소유 API A에서 원 metadata/생장/수확 bytes·UTC를 읽고, 소유 권리를 false로 바꿨을 때
  해당 조회가 거부되는지 확인한다. true로 복원하면 같은 원 bytes를 반환해야 한다.
- A를 실제 종료하고 TCP listener가 사라지는 것을 확인한다. 같은 DB/주소/CA/계정으로
  다른 PID/start identity의 B를 기동해 원 응답·DB/결과 불변을 대사한다.
- 원5서비스/하위 프로세스·두 사용자 HTML/자산·원본2148개와512MiB/PID·합1GiB/600초를
  유지한다. 건강한 기존 API를 시험 때문에 종료하지 않는다. 소유 API/제어 파일/키/FD를 정리한다.

## 후속 브라우저 수용

같은 빌드와 실제 소유 API에서 원 생장/수확을 함께 표시한 뒤, 현재 권리 재조회·권리 철회와
복원·실제 API 중단/재시작을 거쳐 두 수치 화면이 함께 제거/복구되는지 확인한다.
서버가 만든 원 응답을 지연시킨 뒤 취소/계정 변경 시 그 응답이 이전 화면을 복원하지 않아야 한다.
정상200의 값/단위/UTC·원 ID와 거부/장애의 실제 HTTP 상태, 요청 수·종료/정리를 기록한다.
프록시만의 재시작이나 mock 응답으로 실제 API 재시작을 대신하지 않는다.

API 단계의 성공은 브라우저/전체 U1 수용이 아니다. 최신 backend의 구판 CODE 지원,
기존3상태 디자인·다른 저장 모델/전체 기간·사용자 적용과 전체 G1/G0–G4는 계속 별도다.

2026-10-20: [API-only20조회](../research/catalog-owned-api-lifecycle-20261020.md)와
[농장 목록의 실제 늦은200 전달2건 차단](../research/catalog-native-late-response-20261020.md)을
각 범위에서 수용했다. 별도 PG/API+브라우저 동시 시험은 원 RSS 한도로 미수용이다.
이 두 성공을 전체 재시작/권리 브라우저 수용으로 합산하지 않는다.
