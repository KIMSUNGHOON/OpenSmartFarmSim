# 저장 작물 결과 선택 화면 v1

U1의 화면 자식. 개발 선행은 현재 등록 작물/결과 목록 API와 두 SDK의 수용이다.
선택 전달 후보와 화면 구현은 병행할 수 있으나, 화면 수용에는 선행 재생의 남은 브라우저 조건과
이번 화면의 실제 브라우저·원 승인 디자인 대조가 필요하다. 실제 DB/API 통합과 상위 U1은 후속이다.
핵심5파일: 이 계약, `web/src/cropResultPicker.ts`, `web/src/cropResultPicker.test.ts`,
`web/src/CropResultCatalog.tsx`, `web/src/App.tsx`. CSS·원 변환 자산·브라우저 시험은 지원 파일이다.

## 동작

기존08 화면에서 목록 선택 경로를 연다. 기존 수동 조회의 기본 경로와 여덟 내비게이션을 유지한다.
현재 계정의 기존 작성 농장 목록에서 판본을 선택하고, 정확한 등록을 다시 조회해 원 hash가 같은지
확인한 뒤 등록 작물 SDK를 읽는다. 사용자 species/variety·기간은 등록 의도이며 검증된 품종이 아니다.
선택한 crop_id와 farm3으로 같은 farm4의 생장/수확 목록 SDK를 읽는다. 새 계산/등록은 접수하지 않는다.

농장 목록은 최대20개, 결과는 최대10개를 한 페이지씩 보유하고 실제 keyset cursor로 앞/뒤 페이지를 조회한다.
전체 개수/전체 페이지 수·농장 별명·작기 단계·가격/생산량을 만들어 표시하지 않는다.
페이지 이동/새로고침·농장/작물/kind 변경·실패/취소·계정 교체/화면 이탈은 이전 재생 선택을 제거한다.
진행 중 요청은 취소하고 취소할 수 없는 기존 농장 SDK의 늦은 응답도 세대 검사로 무시한다.
한 picker의 요청은 순차 처리한다. 같은 결과 재선택은 같은 선택 객체를 유지한다.

생장 선택은 metadata의 원 result_id/farm4를, 수확 선택은 원 result_id/verified parent_result_id/farm4를
기존 SelectedCropReplay로 전달한다. 원 파일/수치/현재 권리는 기존 query가 다시 검사한다.
metadata는 수치·현재 권리나 관문 승인 증거가 아니다. 합성/미평가·생산 예측 보류와 실시간 미연동을 표시한다.
토큰·결과·원 자료를 브라우저 저장소나 URL에 저장하지 않는다. 재접속 뒤 서버 목록에서 다시 선택한다.

## 수용과 보류

타입/단위 검사는 실제 SDK metadata fixture를 써서 두 kind/원 식별자·등록 hash 변경 거부·페이지 경계·
빈 결과/hold·현재 실패·취소/늦은 성공과 실패·dispose·동일 선택을 확인한다.
현재 모델/입력과 보호 전체 계산/미리보기 identity·기존 배포 파일을 보존하고 원 종료·RSS/정리를 기록한다.

실제 App Chromium에서 농장→작물→원 결과/같은 UTC3D·수확, 새로고침/계정 교체,
빈 목록/실패/취소·늦은 응답·키보드/좁은 폭과 기존 직접 조회를 검증한다.
12ui의 원 desktop-loaded/desktop-empty/mobile-loaded 이미지·HTML을 사용하고,
구현 뒤 각 원 target의 improve kit와 렌더링을 대조한다. 이 검사가 자원 보류이면 후보이며 배포하지 않는다.
진행 중 전체 계산과 연결한 실시간 U3·실제 공동 DB/재시작·기존 다른 판본/U1·품종/농장 관문은 별도다.
