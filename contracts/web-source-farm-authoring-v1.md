# 저장 원천·경제 선택에서 농장 작성으로 연결 v1

상태: 내부 웹 연결 계약, 2026-10-01. [원천 참조 API](api-source-farm-selection-v1.md)와
[경제 목록/현재 선택 API](api-farm-economic-candidate-selection-v1.md)를 기존 작성
폼·검토/Run·경제/평가·3D에 연결한다. 완전 수용 전까지 해당 작업 체크는 유지한다.

## 브라우저 읽기와 입력 연결

기존 Bearer 클라이언트의 전체 본문 30초 제한, 크기 제한과 `no-store`를 유지한다.
`sourceFarmReferences(researchId, collectionId)`는 정확한 UUID 쌍의 닫힌 원천 참조를
읽는다. `sourceEconomicCandidates(source, cursor?)`는 같은 전체 원천 참조와 연결된
저장 메타데이터를 기본 20개씩 읽으며 승인으로 표시하지 않는다.
`sourceEconomicCandidate(source, candidate)`는 선택한 정확한 메타데이터의 후보를
단건 조회하고 동일한 원천·경제 핀·보류·달력·기록 시각인지 다시 확인한다.

소프트웨어 전용/G0·G1 미수용/hold 및 두 검증 표시를 그대로 유지한다. 다른 부모,
시도, 문맥/해시, 결정 시각, 자료 판본, 후보/달력 불일치나 추가 비공개 필드는
표시를 거부한다. 목록은 중복 없이 `(recorded_at, candidate_id)` 내림차순이며
커서는 마지막 행의 정확한 값이다. UTC 소수점 여섯 자리까지 문자열로 보존하고
밀리초로 반올림하지 않는다. 빈 목록·권한·현재 근거 보류는 새 자료를 생성하지 않는다.

선택 성공 뒤 폼에 옮기는 것은 조사 ID, 스냅샷/서명 문맥, 결정 시각,
기존 시장 보류, 경제 핀과 경제 평가 날짜뿐이다. 신규 농장 ID/판본, 시설/제어/재배
수치, 숫자 출처·시각과 권리 선언은 사용자가 명시한다. 미확인 값을 채우지 않는다.
폼은 서버의 결정 시각 정밀도를 그대로 지원한다. 원천이나 경제 조합을 바꾸면
제출 전 확인과 권리 동의를 취소하고 다시 검토하게 한다. 접수 불확실 상태에서는
참조와 입력을 고정하여 기존 동일 바이트 재확인 절차를 따른다.
등록 접수 중이거나 응답이 불확실하면 연결 변경/해제와 다른 화면의 신규 접수·부모 선택도
잠근다. 화면 이동은 허용하며 04 작성 화면에서 같은 등록 요청을 재확인한다.
서버의 검증된 등록 응답 또는 확정 거부 후 잠금을 해제한다. 확정 거부 뒤 입력을 다시
검토할 수 있으며, 잘못된 성공 응답은 접수 불확실 상태를 유지한다.

## 화면·복구와 수용

기존 원천 작업/저장 기록에서 완료 조사와 그 조사에 속한 완료 수집을 선택한다.
현재 참조를 읽은 뒤 경제 목록을 열고 단건을 확인하여 농장 작성으로 이동한다.
원천 선택·경제 선택·입력 작성의 순서, 현재 근거 확인/보류, 빈 목록과 오류,
재연결·계정 변경의 선택 취소를 키보드와 좁은 화면에서 확인한다. 이전 계정/원천의
늦은 응답은 새 선택에 적용하지 않는다. 민감한 입력과 토큰은 브라우저에 저장하지 않는다.
재연결 후 서버 이력에서 다시 선택하고 현재 참조를 다시 확인한다.

12ui의 해당 선택/작성 상태를 확인하고 기존 작성 화면에 통합한 뒤 target close를
실행한다. 생성된 근거 없는 작물·요금·수확·마진·관문 승인은 사용하지 않는다.
형식/다른 원천/페이지/정밀도/보류의 클라이언트 시험, 계정·응답 유실/변경의
브라우저 시험과 실제 HTTPS/SCRAM 신규 등록→검토/작성 Run→경제/평가·같은 3D 경로의
증거를 확인한 뒤 체크한다. 시험용 CLI/해제는 소프트웨어 증거이며 실제 제품 CLI·
독립 해제/전체 G1/G4는 별도 수용이다.
