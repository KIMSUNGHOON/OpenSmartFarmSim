상태: **첫 계산 모듈 명세, 2026-10-04. 아직 코드/작물 프로필 수용 전**.
선행: [모델 조사](../research/crop-tomato-model-baseline-20261004.md), 기존 버전·권리 정책.
모델/판정은 기존 `gpt-6.1-sol / xhigh` CLI 세션에서 검토한다. 정량 계산은
명시적 버전 코드로 한다. 이 계약은 기존 [제품 관문](../docs/PROJECT_SPEC.md#6-검증과-수용-관문)을 유지한다.

## 첫 개발 대상과 입력 경계

개발 참조는 Axiany/Maxifort 한 작기이며, 첫 rate kernel은 고정된 GreenLight/
Vanthoor 문헌식의 일반 매개변수에 대한 **연구 계산**이다. Axiany 전용 보정이나
한국 농장의 미래 생산성을 주장하지 않는다. 전체 Compose 완주·G2·시장 G0가 이
순수 계산 모듈의 착수 조건은 아니다. 외부 실측은 별도 병행 경로로 확보한다.

실행 입력은 모델/매개변수·초기조건 ID와 원문 해시, 각 값의 출처·단위·검토 상태,
수관 온도/평활 온도/온도 합, 실제 또는 명시적 합성 PAR·CO₂, 잎·줄기/뿌리·과실·
탄소 버퍼 상태다. 부정확한 단위, NaN/무한, 음의 질량/광량, CO₂ 0,
지원 범위를 벗어난 값이나 누락된 필수 입력은 고정 오류로 거부한다.
기온→수관 온도, 일사→PAR, 일반 토마토→Axiany 계수의 자동 변환/대체는 없다.

39개 연구 const 등록 항목은 승인 프로필이 아니다. 첫 모듈에 필요한 매개변수만
수식·차원을 대사해 별도 `reference_only` 판본으로 채택한다. 수식 내부 상수와
단위 정정도 원식/해시/정정 근거를 기록한다. `cRgr`는 원 논문에 따라 s이며,
초기조건·변환계수·생리 계수에 출처 없는 새 수치를 넣지 않는다.

## 첫 모듈: crop-growth-rates

예정 파일(3): `backend/app/crop_growth_rates.py`,
`backend/tests/test_crop_growth_rates.py`,
`fixtures/crop-growth-reference-parameters-v1.json`.
아직 존재하지 않는 파일의 실행을 통과했다고 기록하지 않는다.

모듈은 고정된 광 동화·기관 분배·생장/유지 호흡 유량을 계산하며, 버퍼와
기관의 순간 변화율을 함께 반환한다. 단위는 탄수화물 당량 mg CH₂O/m²와
mg CH₂O/m²/s로 고정한다. 잎 면적은 SLA에 의한 m² leaf/m² floor이며,
줄기 상태에는 원 모델의 뿌리 포함 사실을 유지한다. 수확·적엽 유량은 호출자가
지정한 사건/별도 검증 모듈에서 오며 첫 모듈이 임의 수확 시점을 발명하지 않는다.

탄소 유입 − 생장 호흡 − 유지 호흡 − 제거 유량이 저장소 합의 변화율과 같아야 한다.
기관 간 이동은 외부 소비로 중복 차감하지 않는다. 잎 면적 0에서는 광 동화를
명시적 극한으로 처리하고, 양의 잎 면적식과의 연속성을 시험한다. 생리 상태나
출력을 임의로 0에 고정해 실패를 숨기지 않는다. 이진 실수는 물리 유량에 사용하고,
금액을 만들 때는 후속 기존 Decimal 계약을 따른다.

cd backend

## 첫 모듈 수용 기준

1. 필요한 모든 식/매개변수에 고정 원문·단위·권리·정정 이력이 있고, 런타임의
   LLM 텍스트·기본값 주입 없이 같은 입력을 재현한다.
2. 광량 0/잎 면적 0의 광 동화 0, 유한한 호흡·유량, 문헌식의 독립 고정 참조값과
   기관 수지 항등식을 확인한다. 기대값은 구현 함수로 다시 만들지 않는다.
3. 허용 구간의 온도·PAR·CO₂/초기 상태, 특이점·잘못된 단위/비유한·음수 및
   미확인 매개변수의 거부를 시험한다. 수치 오차 예산을 계산 정밀도/조건수에서
   정하고 생물학적 예측 정확도의 합격선과 혼동하지 않는다.
4. CLI 실행 모델/effort·실제 검사 명령/결과·코드/입력 해시와 남은 hold를 기록한다.
   통과는 해당 rate kernel의 계산 계약 범위이며 전체 제품 G1은 아니다.

## 뒤따를 작은 단계와 사용자 산출물

| 단계 | 저장/표현할 실제 계산량 | 수용/제한 |
| --- | --- | --- |
| 적분 | 버퍼·기관·LAI·온도 합, 누적 호흡/제거와 탄소 잔차 | 양수·수지·시간 간격/수렴·원식 참조 재현. 별도 과실 구획 검증 전 숙기/생과 수확 없음 |
| 저장/API | immutable crop result ID, forcing/profile/model/solver·manifest·해시, claim scope/hold, UTC 시점 | 기존 농장/Run/계정 연결·현재 권리·혼합/변조·재시작 검사. 기존 accepted Run으로 승격하지 않음 |
| 성장 3D | 같은 result ID + timestamp의 계산된 잎 면적/기관 상태 | 총 잎 면적은 저장 수치에서 결정. 도형 배치/형태는 모식도 표기. 키·잎수·숙기·열매 개수가 미계산이면 표시/애니메이션하지 않음 |
| 생산량 | 착과/발달 구획·수확 사건·검증된 건물/생과중 환산·등급 | 기관 질량/개수·수확 제거 보존, 시기/밀도·영역·품종 검증. G3a 전 국내 미래 수확 게시 hold |
| 자원 | 물/배지/재순환·성분·CO₂ 및 열/구매 에너지의 별도 수지 | 실제 급액·증산·구매 용수/전력·연료 분리, 기존 작물 계수와 새 계산의 이중 반영 금지 |
| 경제 | 같은 작기/생산 배치의 H/P/S·불량/재고·가격/비용/수금 | 기존 권리·MarketContext·Decimal 경계 유지. 모델 수확을 사용자 가정으로 재분류하지 않음 |

첫 3D는 표·그래프와 같은 모델 상태를 읽는 연구 재생이다. 내부 계산/소프트웨어
시험 결과의 보류 판본과 승인 제품 Run을 분리한다. 해당 입력의 G0·계산/재현 G1
전에는 제품 재생을 열지 않는다. 독립 국내 G2와 미래 작기의 해당 G3a 전에는
국내 미래 생산량·자원·이익을 예측으로 게시하지 않는다. 비교 추천에는 추가 G3b,
공개 배포에는 G4가 필요하다.
