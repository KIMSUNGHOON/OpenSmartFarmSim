# 자동 출현 원 입력의 출처·현재 검토 — v1

상태: [신규71/관련319·390검사와 원 source/fresh 수용](../research/crop-leaf-appearance-input-evidence-20261024.md). [저장 3D](web-leaf-appearance-replay-v1.md) 뒤의 농장 연결 첫 자식이다.
기존 population 입력 증거는 생성한 선언을 검토하며 원 appearance 정책/초기 위치/프로필의 검토를 대신하지 않는다.
새 검증기는 기존 생장·준비·producer/reader·원 지문/결과/서버를 변경하지 않는다.

`LeafAppearanceInputEvidenceAuthority`는 명시 key/issuer/key ID·현재 appearance review resolver와
기존 `MorphologyInputEvidenceAuthority`를 받는다. issue/verify는 원 program/source bytes·신뢰 SHA·
review ID/decision UTC와 원 stem issue arguments/evidence를 받는다. HTTP나 키를 받는 사용자 폼은 추가하지 않는다.

program≤2MiB/source≤1MiB/evidence≤2MiB이고 source는 `leaf-appearance-input-source-v1`의
닫힌 program SHA/기존 SourceRecord다. 모든 unit 객체와 정책의 첫 생식 순번/그 사이 영양 위치 수의
단위 `1`을 경로별로 대사한다. 원 SHA·품목/판본·합성 저자/방법·발표/가용/수신·권리/QC/현재 검토를 확인한다.
모든 입력은 자체 합성이며 재배포 False는 내부 처리와 구분해 거부 권리로 보존한다.

원 appearance parser와 기존 population의 빈 새 선언 구조 검사를 재사용해 원 stem 프로그램의
UTC 원점·초기 정확 초를 대사한다. 저장 reader의 초기 결속으로 같은 shoot/schedule·순번 정책의 영양 위치마다
원 순서의 잎 하나와 같은 부모 출현 초를 요구한다. 미래 출현/기온·곡선/초기 면적 수치는 계산하지 않는다.
stem program SHA/현재 입력 검토는 확인하지만 stem artifact root는 식별자이며
해당 농장/완료 서명 결과와의 일치는 후속 farm binding에서 확인한다.

새 domain/version의 HMAC은 두 입력/현재 검토·원 정책/초기/프로필·초기 부착 지문·모델/코드를 묶는다.
발급/검증 전후 stem 검토와 최종 appearance 검토를 다시 확인한다. 서로 다른 resolver의 원자 snapshot을
증명하지 않으며 게시 시점의 현재 farm 권리는 후속 게시기에서 별도로 검사한다.
metadata는 복사본이고 키를 반환하지 않는다. 게이트 승인/수치 검증/실제 농장 승인을 발급하지 않는다.

수용은 정상 원 bytes/metadata·정책 단위/초기 부착·재배포 False와 rehash 뒤 출처/단위/시각/초기 혼합,
현재/늦은 양쪽 철회·서명/모델/코드 변경 거부, 실제 원 source의 별도 fresh에서 생장 import/계산·DB·CLI·쓰기0,
원 파일/FD·3root/WSL 상한·소유 정리다. 실제 품종/독립 작기0·G0–G4/생산·추천과 전체 실행은 별도다.
