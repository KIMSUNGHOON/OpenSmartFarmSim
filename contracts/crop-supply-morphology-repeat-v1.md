# Repeated supply-limited morphology, research v1

Repeated adoption has bounded synthetic software acceptance in [the verification report](../research/crop-supply-morphology-repeat-20261030.md). A real cultivar or complete crop cycle remains unaccepted.

The new genuine Context/checkpoint family starts from an actual accepted successor Context and trusted successor continuation bytes/hash. It keeps that actual authority, the original physical root, the exact current sample, every birth and geometry/inflow origin, lifetime/point/global accounts, current schedule, original fractional remainder/grid/horizon and output prefix. Existing typed validators remain unchanged. Plain algebra may operate on explicit validated data; older typed handles must never be manufactured.

`prepare_context` validates the actual current input with one birth-stage evaluation. `context_bytes`, `start` and cold Context restoration perform no RHS, material, funding or leaf initialization. `restore_checkpoint` checks exactly the current RHS and never integrates past intervals. Original-grid advance uses the same actual birth-stage RK4 stages, exact binary inputs, balances, source/rights/profile/code fences and failure-prefix rules.

The upstream expected code-hash mapping is immutable for the imported version. Each new-family pin check freshly reads every declared source and checks its expected hash once; it does not recursively rebuild that same mapping. Source bytes, current rights, profiles and authority validation are not cached by this change. Existing ancestor validators and before/after stage fences remain in place. A pin-read complexity check and current-byte corruption checks cover this boundary; an instrumented one-event comparison is not full-horizon performance acceptance.

Repeated adoption must bind the genuine current parent/CP, the first unconsumed source threshold, the cubic upper candidate, explicit versioned compatible seed C/geometry/cost/temperature and the original growth costs. It consumes that schedule once, preserves all previous origins, adds only the new origins and resumes the original fractional remainder. Missing future declarations hold at the actual pending boundary. Future seeds must not be inferred. A single extra seed-only owner does not satisfy this contract.

Use flat immutable receipts with parent and source hashes. Persist complete state/arithmetic/source evidence needed for cold validation, without duplicating every full diagnostic refinement or nesting past candidates. A compact receipt has its own version and hash; it does not pretend to be an unchanged older proposal. Trusted hashes bind bytes, not approval of data or claim gates. Current Context/response2MiB, CP512KiB, inventory512 and32768-scalar limits remain.

The v2 Context stores tagged, lossless receipt references to its genuine immediate parent seed and the current complete code-hash set. Each decoded receipt must match its original canonical byte hash before arithmetic validation. References never target other encoded receipts or remote objects. Both encoded and expanded receipt sizes stay within2MiB; expansion accounts for referenced bytes before copying them. The complete Context bundle retains its2MiB cap. Signed zero, JSON scalar types, IDs, units, clocks and original geometry origins remain exact.

An in-process prepared candidate is issued only after the actual deterministic candidate computation. Its private weak seal binds immutable bytes; raw JSON or a self-rehashed object cannot supply that authority. Reuse requires the same genuine current Context/CP, exact tolerance, current code/profile/source/rights fences and unchanged caller inputs. It skips repeated candidate integration and keeps actual point-call work separate from the attached candidate receipt counts. A new process recomputes a candidate; Context/CP cold restoration remains independent of this ephemeral capability.

Acceptance needs at least two subsequent actual material events followed by the original horizon, mixed optional leaf/zero/nonzero stem declarations, all/split/cold identical final bytes and same ordered IDs/state/clock/global accounts, no past biology/material replay, independent arithmetic and preservation of original assets/services. Rehashed mutations, current/late authority changes, funding/rounding/domain/cap failures and last confirmed prefix must be tested. Immutable storage/reader/SDK and same-state realistic3D follow actual repetition. G0–G4 remain not_assessed and R2 not_approved; real cultivar, full crop-cycle production and recommendations remain outside this synthetic acceptance.
