# Authored farm release verification v1

Status: internal release-verification candidate after a [completed authored CLI review](farm-authored-review-completion-v1.md). It does not issue a reviewer signature, store an approved authored snapshot, publish a Run or grant G1.

The server calls the exact completed-review verifier with a tenant, review job ID and expected registration SHA-256. It requires the existing `ex_post_replay` scope and builds canonical request bytes from the completed proof: original source and snapshot, farm/numeric/rights/binding hashes, signed context and decision time, candidate and both trace hashes, CLI decision/capture IDs, artifact and attempt. The request also hashes every current `backend/app/*.py` file, every `contracts/*.schema.json`, `backend/pyproject.toml`, `backend/uv.lock`, and the pinned CLI executable/environment. Missing required modules, changed bytes or a changed current registration produce a new request digest or hold. The request contains hashes and IDs rather than raw farm or restricted source records.

An external reviewer must issue canonical `farm-authored-release-v1` bytes and an Ed25519 signature over the domain-separated release. The configured reviewer key and identity must differ from the CLI execution observer key. The release binds the exact request and a canonical evidence document. That document binds three separate report byte strings for source rights/QC, numerical recalculation, and runtime custody. Every report must have a pass verdict, a method and at least one tenant-scoped evidence reference; the trusted resolver must retrieve each bounded referenced byte string and match its SHA-256. The verified review time follows the CLI decision, issuance follows review, and issuance cannot be in the future. The server rereads the completed proof and current code after checking the signature. Any mismatch returns a generic hold.

The returned `VerifiedAuthoredRelease` is an immutable packet for a later publisher to check and retain. The packet's structural and cryptographic checks do not establish that a human or independent process actually performed the three reviews. Production signer custody, reviewer independence, report provenance, real CLI execution, code/image equivalence and an atomic authored Run publisher must be evidenced separately. A test key or a signed `pass` string alone cannot clear G1. The scope is synthetic software replay only; G0/G2/G3 claims remain held.
